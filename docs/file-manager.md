# Файловый менеджер

Загрузка файлов любого размера, папки, перенос, переименование, удаление.

## Коротко

| | |
|---|---|
| Где лежат файлы | `storage/app/userfiles/<user_id>/…` (диск `local`, **вне** `public/`) |
| Кто владеет | пользователь; чужой идентификатор выглядит как «не найдено» |
| Право | `files.upload` **или** `content.manage` **или** `courses.manage` |
| Размер файла | до `files.max_bytes` (по умолчанию 4 ГБ) |
| Крупные файлы | режутся на части, докачиваются после обрыва |
| Страница | `/filemanager` (пункт меню «Файлы») |

## Почему загрузка по частям

Лимиты размера запроса стоят не на файле, а на **одном запросе**:

| Где | Параметр | По умолчанию |
|---|---|---|
| PHP | `post_max_size` | 8 МБ |
| PHP | `upload_max_filesize` | 2 МБ |
| nginx | `client_max_body_size` | **1 МБ** |

Файл на 2 ГБ целиком не пройдёт ни при какой настройке, кроме «снять
ограничения», а это плохая настройка. Поэтому файл режется на части по
`files.chunk_bytes` (4 МБ) и отправляется отдельными запросами. Следствия:

* **докачка** — оборванная загрузка продолжается с последней принятой
  части, а не начинается заново;
* **мультизагрузка** — в очереди несколько файлов, у каждого свой
  прогресс;
* **nginx** без `client_max_body_size` отобьёт часть с 413 **до PHP**, и
  в логах Laravel не будет ничего.

Проверить свои значения и получить готовую строку nginx:

```
php artisan files:limits
```

## Настройка

Все параметры — в `config/files.php`, дублируются в `.env`:

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `FILE_MANAGER_DISK` | `local` | диск. **Не** `public`: каталог `public` попадает под корень веб-сервера через `storage:link` |
| `FILE_MANAGER_ROOT` | `userfiles` | каталог внутри диска |
| `FILE_MANAGER_CHUNK_BYTES` | 4 МБ | размер части; должен быть заметно меньше `post_max_size` и `client_max_body_size` |
| `FILE_MANAGER_MAX_BYTES` | 4 ГБ | предел одного файла; `0` — без ограничения |
| `FILE_MANAGER_UPLOAD_TTL` | 24 ч | сколько живёт незавершённая загрузка |
| `FILE_MANAGER_MAX_BULK` | 500 | сколько файлов можно переместить/удалить одним действием |

В nginx (рядом с блоком раздачи материала):

```nginx
client_max_body_size 8m;      # больше размера части
client_body_timeout  300s;    # медленный канал
client_body_buffer_size 64k;
fastcgi_request_buffering off;
```

## Уборка незавершённых загрузок

Части лежат во временном каталоге и занимают место. Загрузка, брошенная
на середине, сама не исчезает:

```
php artisan files:prune-uploads
```

Идемпотентна, годится для cron:

```
*/15 * * * * cd /var/www/lms && php artisan files:prune-uploads >> /dev/null 2>&1
```

## API

Ответы — в общем конверте `{success, data, error, meta}`.

| Метод | Путь | Что делает |
|---|---|---|
| `GET` | `/api/filemanager?folder_id=` | содержимое каталога: папки, файлы, крошки, пределы |
| `GET` | `/api/filemanager/folders` | всё дерево папок (для выбора папки назначения) |
| `POST` | `/api/filemanager/folders` | создать папку `{name, parent_id?}` |
| `PATCH` | `/api/filemanager/folders/{id}` | переименовать `{name}` |
| `POST` | `/api/filemanager/folders/{id}/move` | перенести `{parent_id}` |
| `DELETE` | `/api/filemanager/folders/{id}?recursive=1` | удалить; без `recursive` непустая папка даёт 422 |
| `PATCH` | `/api/filemanager/files/{id}` | переименовать `{name}` |
| `POST` | `/api/filemanager/files/move` | перенести `{ids: [], folder_id}` |
| `POST` | `/api/filemanager/files/delete` | удалить `{ids: []}` |
| `DELETE` | `/api/filemanager/files/{id}` | удалить один |
| `GET` | `/api/filemanager/files/{id}/download` | скачать |
| `POST` | `/api/filemanager/uploads/init` | начать/продолжить загрузку |
| `POST` | `/api/filemanager/uploads/{id}/chunk?index=N` | часть, тело `application/octet-stream` |
| `POST` | `/api/filemanager/uploads/{id}/complete` | собрать файл |
| `DELETE` | `/api/filemanager/uploads/{id}` | отменить загрузку |

### Протокол загрузки

```
init    → { filename, size, mime?, last_modified?, folder_id? }
        ← { upload_id, chunk_bytes, total_chunks, received[], received_bytes }
chunk   ← тело запроса, GET ?index=N      (× total_chunks)
complete→ { file }
```

`init` идемпотентен по отпечатку `(user_id, имя, размер, mtime)`: повторный
вызов с теми же данными возвращает **тот же** `upload_id` и список уже
принятых частей. Это и есть докачка — клиенту не нужно ничего хранить.

## Правила, которые нельзя нарушать

* **Имя проверяется на входе** (`EntryName`): запрещены `/`, `\`, NUL,
  управляющие символы, ведущая и хвостовая точки, `.` и `..`. Молча
  «очищать» имя нельзя — пользователь получил бы папку, которой не
  просил.
* **Путь проверяется на выходе** (`Location::isInsideUserRoot`): `realpath`
  обязан лежать внутри каталога пользователя. Это ловит симлинк, который
  прошёл проверку имени.
* **Всё выбирается по `user_id`.** Чужой идентификатор обязан выглядеть
  как отсутствующий: иначе по реакции на запрос перебирается чужой
  каталог.
* **Сначала диск, потом база.** Обратный порядок даёт запись о файле,
  которого нет: пользователь видит файл и не может его открыть.
* **Непустая папка не удаляется молча** — требуется явный `recursive`.
* **Совпадение имён не перезаписывает файл**, а получает суффикс
  `«(2)»`. Номер у уже занятого имени снимается: `отчёт (2).pdf` →
  `отчёт (3).pdf`, а не `отчёт (2) (3).pdf`.

## Старые загрузки

У записей `files`, созданных до менеджера, `path = null`: они лежат по
двум разным старым схемам (`uploads/{ФИО}` и `/public/{ФИО}_{id}/{тип}/`).
Менеджер их не показывает и не выдумывает для них путь. Старый
`POST /api/files/add` продолжает работать.
