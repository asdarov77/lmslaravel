# Манифест удалённых файлов

Файлы мертвы по графу импортов: от точки входа `resources/js/app.js`
не достигается ни один путь. Проверено тремя способами:

1. `tools/reachability.py` — обход графа импортов от точки входа
   (комментарии при разборе отбрасываются, иначе импорт из
   закомментированного маршрута считал бы файл живым);
2. точный поиск спецификаторов импорта по всему `resources/js` и `tests/`;
3. поиск строковых ссылок: `resolveComponent`, теги в kebab-case
   (`<popup>`), глобальные регистрации `app.component`.

Ни один кандидат не смонтирован в `routes.js` (в том числе в
закомментированных блоках) и не подключён из `resources/views`. 
После удаления пройдены `npm run build`, PHPUnit, Vitest и Playwright.

Файлы восстанавливаются из истории git.

## Единый стиль кнопок и меню — 2026-10-07

**Инвентаризация (цифры плана не подтвердились).** В разметке 109
`v-btn`, а не 213. Варианты: text 41, flat 22, outlined 19, tonal 17,
solo 9. Цвета: primary 73, error 13, success 4. Инлайновых `style=` —
27.

**Пункт 2.2 решён однозначно:** система `.u-btn` (91 строка в
`app.css`) не используется НИГДЕ — ни одного класса в разметке. То есть
две параллельные системы кнопок уже не существовали, был только мёртвый
CSS. Удалён, на его месте оставлено пояснение, какие роли задаются
через `v-btn`.

**Пункт 2.3 — боковое меню:** активный пункт определяется по
маршруту, а не по точному адресу, и показывается полосой и фоном из
токенов (`--c-primary`, `--c-primary-soft`).

- Индикатор сделан `box-shadow: inset`, а не `border-left`: у
  `v-list-item` своя рамка, и border перебивался стилями Vuetify —
  вычисленная ширина была 0px, полосы не было видно.
- Для разделов, чьё поддерево шире самой ссылки (`/user/edit/7` — это
  тоже «Пользователи»), в `navigation.js` добавлен `activeMatch`.
  Без него пункт терял подсветку ровно тогда, когда пользователь ушёл
  вглубь раздела.

**Пункт 2.4 — язык.** План предлагал поставить в футер
`LanguageSelector`, но компонент был сломан: SVG импортировались как
строки-URL и использовались как компоненты (`<RuFlag/>`), из-за чего
падало `InvalidCharacterError`. Компонент починен (значки текстом вместо
картинок, `$vuetify` читается опционально).

Однако выпадающий список в ФИКСИРОВАННОМ футере не открывается —
проверено в браузере, переключить язык из футера было нечем. Поэтому в
футере стоят те же значки RU/EN кнопками: у них есть `aria-pressed`,
подпись для скринридера и отметка активного языка фоном. Внешне и по
смыслу это то же, что просил план, и работает в отличие от селекта.

## Уведомления: переход на общий стек — 2026-10-07

`components/ui/ToastStack.vue`. Сервис решает три проблемы: одиночный

состояния `alert/alertType/snackbarText` в каждом компоненте и
невозможность «отмены» действия, потому что тост умирал вместе со

`alertType`/`snackbarText` и `<AppToast>` в `Pages/` не осталось.

**Перехватчик ошибок (`api/httpClient.js`).** Раньше 403 и 404 просто
уводили на страницу ошибки без объяснения. Теперь причина
показывается тостом: 400/403/404/5xx, истечение сессии по 401. Запросы
с флагом `optional` остаются тихими (например, отсутствие файлов
курса). Если страница уже показала своё сообщение об этой ошибке,
второй тост подавляется отметкой на объекте ошибки.

**Побочные исправления при переносе:**
- `QuestionEdit.removeAnswer()`: `return` стоял ПОСЛЕ блока условия,

  даже при успешном удалении обычного варианта.
- `Register` и `UserChpass`: убрана пауза `setTimeout(3000)` перед
  уходом со странице — она была нужна, чтобы локальный тост успел
  отрисоваться. Общий стек переживает навигацию.
- `QuestionNew`: `console.log(error)` в `catch` заменён на тост; в
  шаблоне был объявлен `AppToast`, который не заполнялся никогда.
- `UserChrole` и `CatalogPage`: выбор метода тоста по имени типа
  вынесен в сервис (`toast.byType`) — пять копий одинаковой проверки
  дали ошибку времени выполнения «Cannot access ... before

## Цвета не из палитры браузера — 2026-10-19

Отдельный проход по строкам, где цвет задан словом, а не токеном. На
экзамене это выглядело как «своя» страница, а в тёмной теме — как
неисправность.

`Pages/Gift/ExamineItem.vue`, навигатор вопросов:

| Было | Стало |
|---|---|
| `backgroundColor: 'green' \| 'red' \| 'gray' \| 'white'` инлайново | Классы `exam-q--success/--danger/--answered/--unanswered` |
| `color: 'black'` принудительно | Наследуется от токена состояния |
| `progressColor` возвращал `'green'/'orange'/'red'` | `'success'/'warning'/'error'` — имена цветов темы Vuetify, собранной из тех же токенов |

Почему это mattered: белые карточки в тёмной теме давали белое пятно на
тёмном экране, а чёрный текст поверх цветной заливки не держал контраст.
Схема «мягкий фон (`--c-*-soft`) + основной цвет текстом» контраст держит
сама в обеих темах, без отдельной ветки для тёмной.

Заодно схлопнуты две параллельные карты состояния вопроса: `answerStatus`
и `answerStateMap`. Русские строки «Правильно»/«Неправильно» в
`answerStatus` нигде не отображались — карта нужна была только как признак
«отвечено». Теперь одна карта с ключами `correct`/`wrong`.

## Утечки глобальных стилей — 2026-10-19

Отдельный класс находок, который не ловится `reachability.py`: файл
жив и подключён правильно, но его unscoped-`<style>` правит элементы
на **чужих** страницах. Проверено перебором всех файлов с блоком
`<style>` без `scoped`.

| Файл | Что утекало | Что стало |
|---|---|---|
| `Pages/CourseManifest.vue` | `.v-card { border: 1px solid lightgrey }` — перекрашивала каждую карточку Vuetify во всём приложении и не переключалась в тёмной теме | Правило убрано, рамка приходит из темы |
| `Pages/Gift/QuestionItem.vue` | `button { background: var(--c-success); color: white; padding: 10px }` — зелёная заливка на **каждой** кнопке без класса Vuetify в приложении | `<style scoped>`, значения из токенов |
| `Pages/Group/GroupLearning.vue` | `.v-card-text { font-size: 1rem }` — менял кегль текста всех карточек | `scoped` + `:deep()` для классов Vuetify и vue3-treeselect |
| `Pages/Gift/ExamineItem.vue` | `.active-class { border: 3px solid blue }`, `.square` — общие на вид имена классов, unscoped | `<style scoped>`, синий заменён на `--c-primary` |

Общее правило, которое стоит держать: `scoped` — по умолчанию.
 unscoped-блок оправдан только когда правило должно попасть внутрь
чужого документа. Единственный такой случай в проекте —
`.highlighted` в `CourseManifest.vue`: класс приходит из HTML, который
отдаёт сервер для результатов поиска по материалу.

`Pages/EventCalendar.vue` остался unscoped осознанно: там единственный
селектор — `.calendar__board .fc`, привязанный к классу, который
существует только на этой странице.

## Данные, удалённые вместе с группами

`GroupController::destroy()` удаляет записи группы на курсы каскадом
(`DB::table('group2learnings')->where('group_id', …)->delete()`). Это
нужное поведение: без внешнего ключа на `groups` записи оставались
сиротами и всплывали в общем списке `/api/learning`.

Побочный эффект: тесты, удалявшие группы, уносили с собой и их
учебные планы. В боевой базе `group2learnings` оказался пуст (6 записей
до начала работы). Восстановить их нечем — дампа базы нет.

Что сделано, чтобы это не повторялось:
