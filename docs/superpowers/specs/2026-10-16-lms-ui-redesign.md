# Дизайн LMS: полная переработка интерфейса — письменное решение

> Основная спецификация и дорожная карта: `docs/design-redesign-plan.md` (сверена с кодом октябрь 2026). Документ ниже фиксирует решения по открытым вопросам из п. 8 дорожной карты и перечисляет, что осталось сделать. Принято без опросов — по запросу пользователя «просто делай».

## Интент и почему

Приложение — LMS для обучаемых, инструкторов и менеджеров (Ларавел + Vue 3 + Vuetify 3 + Vite). Интерфейс сейчас живёт в одной системе (`u-card`/`PageHeader`/`DataTable` + токены `resources/css/tokens.css`), но не доводён до состояния «полноценной платформы»: нет единого подхода к состояниям списков, не закрыты все страницы под токенами, остались хардкод-строки, не proven page transitions/e2e. Цель — довести интерфейс до конца существующей дорожной карты, не вводя новых UI-библиотек.

## Цели (goals)

1. Единственный визуальный язык на всех ~40 маршрутах: `PageHeader + u-card + DataTable/FormCard`, токены — единственный источник цветов/радиусов/теней/отступов.
2. Каждый экран: 4 состояния — loading (скелетон), empty, error (retry), success.
3. Сложные формы: схема → `FormCard`/`FormField` → `useForm` → dirty-guard → автосохранение черновика; ручные `fieldErrors` запрещены.
4. Motion ≤ 250 мс, ease-out; страховка `prefers-reduced-motion`.
5. Все пользовательские строки через `$t()` в `ru.json/en.json`.
6. Проверка: `npm run build` green, `npm test` green, `tools/lint-design-pillars.sh` green, e2e smoke (вход → курс → экзамен → результат) green.

## Не цели (non-goals)

- Новая UI-библиотека (zadnych parallel UI kits; только Vuetify 3 + `components/ui`).
- PWA/мобильное приложение — только веб (по решению).
- Бэкенд-зависимые фишки без эндпоинтов: переупорядочивание узлов курса, WYSIWYG-редактор материала (+ санитизация, `sandbox` iframe), поля расписания курса и назначение группам, агрегаты дашбордов («топ-курсы», «работы на проверку»), рекомендованные курсы. Это Фаза 4 бэкенда — не фронт-задача.
- Смена брендовых цветов/логотипа — бренда не дано, остаёмся на палитре из токенов (`primary #1a5fb4`, `accent #0d9488`).

## Анти-цели (anti-goals)

- Не добавлять `elevation-12`, `<v-toolbar>` внутри карточек форм, фиксированные `style="width:`, hex-цвета вне `tokens.css` на новых или мигрированных страницах.
- Не вводить блоки на дашбордах, для которых нет данных в API («выдуманный блок хуже отсутствующего»).
- Не менять стек формы: свой `useForm` уже внедрён ( zod/vee-validate не добавляем).

## Ограничения (constraints)

- `resources/css/tokens.css` — единственный источник правды для цвета, типографики, отступов, радиусов, теней, длительностей анимации.
- `resources/js/Vuetify/index.js` читает те же токены через `getComputedStyle` — дублировать значения в JS нельзя.
- Анимация: `--dur-fast/base/slow`, ease-out; `prefers-reduced-motion` отключает движение.
- Стек иконок — только MDI.

## Решения (вместо опросов пользователя)

| Вопрос | Решение (мой вызов) |
|--------|---------------------|
| Вход по ФИО или email/табельный? | Email/табельный — стандарт для внутреннего LMS. |
| Целевая аудитория: веб или PWA? | Только веб; mobile bottom-nav оставляем для обучаемого (как в плане). |
| Бренд: свои цвета/логотип? | Не даны — остаёмся на палитре токенов. |
| Формы: свой `useForm` или zod+vee-validate? | Свой `useForm` (уже внедрён). |
| Что из Фазы 4 делать первым? | Отчёты и аналитика (`/reports`) — greatest value для «полноценной LMS». |

## Осталось сделать (по аудиту п. 8 дорожной карты)

1. Аудит текущего состояния vs дорожная карта (линтер pilarов, build, тесты, i18n).
2. Проход по качеству: контрастность AA, focus-visible, labels, aria-live, клавиатурная навигация таблиц и дерева курса.
3. i18n: вынести хардкод (`Добавление курса`, лейблы Login/RegisterCourse и т.п.).
4. Состояния всех списков: скелетон/пусто/ошибка(retry) повсюду; optimistic updates в таблицах.
5. Page transitions (fade+slide 200 мс) на всех маршрутах + prefers-reduced-motion.
6. E2E smoke Playwright: вход → курс → экзамен → результат.
7. Зафиксировать в этом документе: пункты 4–7 из «Что требует бэкенда» — не frontier фронта.

## Символ # в адресной строке

Роутер на `createWebHashHistory()`, адрес вида `http://host/#/dashboard`.
Подробный порядок перехода на чистые адреса — `docs/design-redesign-plan.md`,
раздел «Символ # в адресной строке»: сначала `try_files` в nginx, потом
`createWebHistory()`, потом ссылки в письмах и проверка прямого входа.
Laravel-сторона (`Route::fallback`) уже готова и блокирующим не является.

## Что требует бэкенда (неfrontend, зафиксировано честно)

- Переупорядочивание узлов курса (операции «переставить» в `aukstructure`).
- WYSIWYG материала + санитизация HTML + `sandbox` для `srcdoc`-iframe.
- Поля курса `opens_at`/`closes_at` + назначение группам в `courses`/`courseRules()`.
  Агрегаты дашборда: «топ-курсы», «работы на проверку» в `GET /api/dashboard/summary`.
- Подборка «рекомендованные курсы» (прогресс, а не каталог).
