# Раздача материалов курсов: php или nginx

## Коротко

| | `php` (по умолчанию) | `nginx` |
|---|---|---|
| Кто отдаёт файл | Laravel (`response()->stream`) | nginx (открывает файл сам) |
| Байты проходят через PHP | да | нет |
| Требует настройки веб-сервера | нет | да |
| Скорость отдачи | ограничена worker'ами PHP | sendfile, без копирования в userspace |
| Защита подписью | та же | та же |

Переключается галкой: **Настройки → Раздача материалов**. Значение лежит в
`settings.content_delivery` (`php` | `nginx`) и перекрывает переменную
окружения `PRIVATE_CONTENT_DELIVERY`.

`php` — режим по умолчанию не из любви к PHP, а потому что он работает
везде, где есть PHP. Включать `nginx` без настроенного `location` значит
получить пустые страницы материала.

## Почему при нагрузке упирается именно php-режим

Страница материала — это не один файл. Браузер открывает `index.html`, а
затем тянет стили, скрипты, картинки, шрифты: на курсе это сотни запросов.
В режиме `php` каждый байт файла идёт через PHP-FPM, и worker занят всё
время отдачи. Дальше кончается не CPU, а пул воркеров: под нагрузкой
страницы начинают отдавать 502, хотя процессор ещё не загружен.

В режиме `nginx` Laravel отвечает мгновенно и пустым телом с заголовком
`X-Accel-Redirect`, а файл открывает сам веб-сервер через `sendfile`.
PHP в этом запросе не участвует вообще.

## Что НЕ меняется при переключении

Переключатель меняет только то, кто отдаёт файл. Проверка доступа остаётся
в приложении и состоит из двух частей:

1. `middleware ValidatePrivateContentSignature` — HMAC-подпись
   `aircraft|auk|expires` на `APP_KEY` встроена в путь
   (`api/private/{aircraft}/{auk}/{expires}/{signature}/...`), TTL 30 минут.
   Подпись выдаётся только авторизованным через `GET /api/private/signed-url`.
2. `CourseAccess::authorizeOpen` — материал открыт тому, кто записан на
   курс, либо тому, кто курсами управляет.

`X-Accel-Redirect` отдаётся **после** обеих проверок и только если файл
существует. Получить заголовок без проверки нельзя: он не приходит из
среды, его формирует контроллер.

Три независимые проверки стоят перед тем, как nginx увидит путь
(`PrivateContent::accelUri`):

- каждый сегмент проходит `sanitizeSegment` (запрещены `.`, `..`, `/`, `\`, NUL);
- `realpath` результата обязан лежать внутри каталога контента — это ловит
  симлинки, которые прошли первый пункт;
- сегменты кодируются поштучно, поэтому `%2e%2e` доезжает до nginx как
  данные, а не как разделитель пути.

Подпись в `X-Accel-Redirect` не попадает: она ушла бы в логи nginx и в
ответ, который кэшируют.

`Cache-Control` ответа — `private`. Подпись одна на всех записанных на
курс, и общий кэш (CDN, Varnish) отдал бы файл тому, кто её не получал.

## Настройка nginx

Готовый конфиг: `deploy/nginx-content-delivery.conf` (подставьте свой `root`,
путь к контенту и сокет PHP-FPM).

```nginx
# В http{} — sendfile включает отдачу без копирования в userspace.
# Без него X-Accel-Redirect всё равно работает, но без выигрыша в скорости.
sendfile on;

server {
    # Корень приложения: /var/www/lmslaravel/public
    root /var/www/lmslaravel/public;
    index index.php;

    # Каталог контента. Должен совпадать с courses_path приложения,
    # иначе nginx отдаст 404 вместо материала.
    #
    # internal — главное. Такой location недоступен снаружи: прямой
    # запрос к нему отвечает 404. Открыть его можно только заголовком
    # X-Accel-Redirect, который выдаёт Laravel после проверки подписи.
    location /_protected-content/ {
        internal;
        alias /var/www/lmslaravel/storage/app/public/private/;

        # Не отдавать как вложенный рендеринг.
        types { }
        default_type application/octet-stream;

        # Отдаём только существующие файлы.
        try_files $uri =404;

        # Файлы большие и меняются редко: кэш на стороне браузера
        # безопасен, потому что в ответе уже стоит private.
        add_header Cache-Control "private, max-age=600, must-revalidate" always;

        # Уже включено на уровне http{}, но дублируем рядом с alias:
        # забытая директива в этом location съела бы весь выигрыш.
        sendfile on;
    }

    # Клиент не должен видеть содержимое каталога контента, даже если
    # кто-то выполнил `php artisan storage:link` и создал public/storage.
    location /storage/ {
        deny all;
        return 404;
    }

    location / {
        try_files $uri $uri/ /index.php?$query_string;
    }

    location ~ \.php$ {
        include fastcgi_params;
        fastcgi_pass unix:/run/php/php8.2-fpm.sock;
        fastcgi_param SCRIPT_FILENAME $document_root$fastcgi_script_name;
    }
}
```

Имя location (`/_protected-content/`) должно совпадать с
`private_content.accel_internal` в `config/private_content.php` — иначе
`alias` не сработает. Текущее значение видно прямо на странице настроек.

### Порядок включения

1. Разложить конфиг, `nginx -t`, `systemctl reload nginx`.
2. `php artisan content:check-exposure` — убедиться, что каталог контента
   не отдаётся веб-сервером напрямую.
3. Открыть `.../api/private/<самолёт>/<курс>/<expires>/<signature>/index.html`:
   должен прийти ответ **200 с пустым телом** и заголовком `X-Accel-Redirect`.
   Если файл пришёл целиком — включён `php`-режим. Если 404 — не сходится
   `alias`.
4. Только потом включать галку в интерфейсе.

Откат — галка обратно в `php`, перезагрузка nginx не нужна.

## Что НЕ подходит

**Kafka.** Это брокер сообщений, а не сервис отдачи контента браузеру.
Раздачу файлов через неё не сделать. Kafka имеет смысл для фоновых задач
(сборка курса, индексация содержимого), и это отдельная работа.

**S3.** Быстрый и надёжный вариант для высокой нагрузки, но материал
уезжает во внешнее хранилище. Если данные нельзя выносить наружу,
`nginx` даёт большую часть выигрыша без их перемещения.

**`secure_link` вместо подписи в приложении.** nginx умеет проверять
MD5-подпись сам, и тогда повторные запросы не доходят до PHP даже на
проверке. Но подпись становится MD5 и живёт в конфиге nginx, а не в коде:
её проверка перестаёт быть частью бизнес-логики, и её не покрывают
тесты Laravel. Имеет смысл, когда профилирование показало, что именно
проверка подписи — узкое место. Для начала X-Accel-Redirect дешевле и
безопаснее с точки зрения поддержки.

## Чего X-Accel-Redirect не решает

Страница материала — это не только файлы. Дерево тем, список курсов,
подпись, проверка прав, отдача JSON — всё это по-прежнему генерирует
PHP. Если после переключения узкое место осталось, профилировать нужно
именно эти запросы: скорее всего это ранний ответ приложения, а не отдача
файлов, и лечится это кэшем, а не nginx. См. `docs/rbac.md` про области
видимости: `/api/course` и `/api/coursemanifest` отдают контент структуры,
а не файлы.

## Приём загрузки: это другой класс запросов

Материал nginx **отдаёт**, а файловый менеджер принимает **тело
запроса**. Настройки для этого другие, и по умолчанию они мешают:
`client_max_body_size` в nginx — 1m, то есть запрос большего размера
отбивается с 413 ещё до PHP, и в логах Laravel не остаётся ничего.

```nginx
client_max_body_size 8m;      # больше размера части (files.chunk_bytes)
client_body_timeout  300s;    # медленный канал
client_body_buffer_size 64k;
fastcgi_request_buffering off;
```

Подробности загрузки по частям — `docs/file-manager.md`, значения для
своей машины печатает `php artisan files:limits`.

## Проверка: nginx поднимается локально и проверяется браузером

`tools/verify-nginx-delivery.sh` поднимает настоящий nginx перед
`php artisan serve`, включает режим `nginx` и проверяет, что:

* боевой конфиг проходит `nginx -t` (директивы распознаются, location не
  конфликтуют);
* прямой запрос к `/_protected-content/` снаружи даёт 404 — `internal`
  работает;
* подписанный URL отдаёт файл целиком;
* файл отдал **nginx**, а не PHP: во внутреннем location проверки
  ставится заголовок-метка, и в ответе PHP её нет;
* вложенные ресурсы материала (стили, картинки) отдаются с 200;
* `/storage/private/…` закрыт;
* часть файла размером `files.chunk_bytes` принимается nginx'ом;
* Playwright открывает материал в браузере (`tests/E2E/nginx-course-delivery.spec.js`).

```
tools/verify-nginx-delivery.sh              # всё сразу
tools/verify-nginx-delivery.sh --keep       # не гасить процессы
tools/verify-nginx-delivery.sh --no-browser # без браузерной проверки
```

Если nginx в системе нет и нет прав root, скрипт распакует бинарник в
`~/.cache/lms-nginx` и запустит его от текущего пользователя на
непривилегированном порту. Настройку раздачи скрипт возвращает в исходное
значение на выходе.

Без nginx в системе `npm run test:e2e` работает как раньше: тест
раздачи через nginx **пропускается** с объяснением, а не падает.

## Проверки

* `tests/Feature/ContentDeliveryTest.php` — оба режима, приоритет
  настройки над config, кодирование URI, отказ обходу пути, отсутствие
  `X-Accel-Redirect` при недействительной подписи и на 404.
* `tests/Unit/components.settings.delivery.spec.js` — галка берёт
  состояние из ответа сервера и откатывается при ошибке.
* `tests/E2E/nginx-course-delivery.spec.js` — браузерная проверка через
  настоящий nginx: материал открывается, вложенные ресурсы отдаются,
  обход подписи не проходит. Без nginx пропускается.
* `tools/verify-nginx-delivery.sh` — полная проверка на живом nginx,
  включая приём больших запросов.
* `php artisan content:check-exposure` — каталог контента не отдаётся
  веб-сервером напрямую.

## Дыра, найденная при этой работе, и как она закрыта

Контент лежал в `storage/app/public/private/`, то есть внутри публичной
части storage. `php artisan storage:link` — обычный шаг деплоя, и он
создаёт `public/storage -> storage/app/public`, после чего весь материал
доступен по адресу `/storage/private/<самолёт>/<курс>/<файл>` **без
проверки подписи**. Диск `private` был объявлен с
`visibility => public` и `url => /storage/private`, что прямо подсказывало
такой путь.

Сделано в два приёма:

1. `visibility` переведён в `private`, `url` убран.
2. **Каталог вынесен за пределы `public/`**: `storage/app/courses/private/`.
   Перенос выполнен командой `php artisan content:relocate` (7000+ файлов
   переносятся переименованием, то есть мгновенно и без второй копии;
   команда считает файлы и байты до и после и отказывается переносить
   каталог внутрь `public/` или `storage/app/public`).

Теперь `php artisan content:check-exposure` молчит: симлинк
`storage:link` материал не открывает.

### Как менять `COURSES_PATH` (например, на отдельный том)

Всё это делает один сценарий — `tools/migrate-content-storage.sh`.
Он нужен потому, что перенос ломает отдачу материала в промежутке между
шагами: пока конфиг указывает на старое место, а материал уже переехал,
сайт отдаёт 404, и пропущенный шаг оставляет машину в этом состоянии.

```
tools/migrate-content-storage.sh --dry-run    # план, ничего не меняет
tools/migrate-content-storage.sh --yes        # выполнить
tools/migrate-content-storage.sh --yes --to=/var/lib/lms/private
tools/migrate-content-storage.sh --yes --skip-browser
```

Что он делает по шагам:

1. предпроверки — свободное место (нужно только при копировании, то
   есть когда каталоги на разных ФС), занятые файлы, отказ от цели
   внутри `public/`;
2. пробный перенос;
3. перенос и сверка числа файлов и байт;
4. правка `COURSES_PATH` в `.env` с бэкапом (`.env.bak-<метка>`);
5. `config:clear` и проверка, что приложение видит столько же файлов;
6. генерация фрагмента nginx с подставленной меткой;
7. `content:check-exposure`;
8. `tools/verify-nginx-delivery.sh` — отдача живым браузером.

Сценарий безопасен при повторном запуске: если материал уже перенесён,
он скажет об этом и пройдёт дальше. Останавливается он только если
после переноса приложение видит не то число файлов, — и печатает, что
исправить, вместо того чтобы объявить успех.

Остаётся руками только вставить фрагмент в конфиг nginx и сделать
`nginx -t && systemctl reload nginx`: путь к вашему конфигу скрипт не
угадывает, а молчаливый rewrite чужого конфига хуже лишнего шага.

Порядок вручную выглядит так же:

```
php artisan content:relocate --dry-run --to=/var/lib/lms/private   # план
php artisan content:relocate --to=/var/lib/lms/private             # перенос
# в .env:  COURSES_PATH=/var/lib/lms/private
php artisan config:clear
php artisan content:nginx-config            # новый alias для nginx
#   вставить в конфиг, nginx -t && systemctl reload nginx
php artisan content:check-exposure          # должен замолчать
tools/verify-nginx-delivery.sh              # отдача живым браузером
```

Расположение настраивается одной переменной, а не правкой кода: контент
читают `config('app.courses_path')` (AircraftController, PrivateController,
`content:nginx-config`) и nginx `alias` во внутреннем location. Команда
`content:nginx-config` печащает `alias` из того же источника, что и
приложение, поэтому разойтись они могут только если в конфиг nginx
забили путь руками.

Единственное место, где путь к контенту был зашит в коде, —
`FileLoadAndExtractController::extract()` распаковывал zip в
`storage_path('app/public/private')` мимо конфига. Теперь идёт через
`config('app.courses_path')`; иначе после переноса импорт курса молча
создавал бы вторую копию материала там, откуда его уже никто не читает.

Что реально настроено и проверено на живых запросах, какие ошибки-ловушки
встретились при настройке (в том числе почему режим `nginx` без nginx
отдаёт пустое тело со статусом 200) и что делать на боевой машине —
`docs/nginx-x-accel-setup.md`.
