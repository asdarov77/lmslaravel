## 1. Что показал сравнительный анализ с первоначальной версией

### 1.1. Модель данных (БД) — НЕ менялась, и это хорошо

В оригинале (merged_all.txt, `AircraftController::parsemanifest` + `RecurseXML`) при
импорте АУК в класс (самолёт) строилось ровно это:

| Сущность | Кто заполнял | semantics |
|---|---|---|
| `aircrafts` (класс/самолёт) | `storeclasses()` | папка `/courses/<КЛЕН>/` |
| `courses` (АУК) | `parsemanifest()` | папка `<КЛЕН>/<АУК-01>/` |
| `aukstructures` | `RecurseXML()`, тип из `$description = ['название','тема','раздел','модуль']` | дерево: тема(1) → раздел(2) → модуль(3), parent_id |
| `links` | только для `type == 3`: `if ($auktype == 3 && $resources[$attrs_ident]) { Link::updateOrCreate(...) }` | **link на html-файл был ТОЛЬКО у модуля** |
| `categories` + pivot | из `<category>` манифеста | специальность; запись группы шла на категорию класса |

Пользовательский поток оригинала: группу записывали на материал по специальности
(`group2learning` → категория в рамках aircraft) → внутри курса кликабельны были
**только листья-модули** (`item.type === 3 ? getlink(item.id) : ''`), темы и разделы
были подписями. Это подтверждается и в старом фронте, и в новом — модель сохранена.

### 1.2. Что изменилось в текущей версии (и где появились тормоза)

Изменения правильные по смыслу, но почти все — «за» безопасность и доступность,
«против» производительности. Ни одно горячее место оригинала не было оптимизировано,
зато добавлены новые сетевые round-trip'ы.

**Открытие страницы курса (задержка до первого кадра). Цепочка запросов сегодня:**

1. Витрина/каталог открывает маршрут и гоняет **6 параллельных dispatch'ей Vuex**
   (`fetchCourse`, `fetchCategory`, `fetchCategories`, `fetchAircrafts` ×2, `fetchAircraft`)
   плюс `getFavorites()` — дублирующий вызов `fetchAircrafts` уже зафиксирован в коде.
2. Отдельный `$api.get('/api/course?course_id=…&category_id=…')` (фильтр-эндпоинт) —
   второй источник правды о курсе.
3. **Главное узкое место бэкенда:** `CourseController::index` через `CourseFilter`
   грузит `Course::with(['categories', 'aukstructures.links'])` — жадная загрузка ВСЕГО
   дерева aukstructures со ВСЕМИ links без пагинации, без `select()`, без кэша. Для АУК
   на 180–500 узлов это сотни строк JSON на каждое открытие.
4. Затем **цепочка из 3 последовательных HTTP-запросов** на первый материал:
   `GET /api/getlink/{id}` → `GET /api/private/signed-url` → `GET <base>+file (html)`.
   Оригинал обходился одним `getlink` (прямая ссылка в iframe). Подпись добавила
   минимум +2 RTT до появления текста.
5. `getlink()` сам по себе расточителен: ~7 запросов (`Aukstructure::with('course')`,
   ещё один `Aukstructure::find`, `Link::where`, `Course::where->first`,
   `Aircraft::find`, `Aukstructure::where(...)->get()->pluck('id')->first()` — полный
   выбор type=3 по курсу ради одного id, `Link::where(firstId)`), часть из них —
   исторические «костыли» после фикса null-крашей, и они тянутся в каждом открытии.

**Проигрывание (листание материалов, поиск, прокрутка):**

- Каждое переключение модуля = вся цепочка `getlink → signed-url → fetch(html)` снова,
  **без какого-либо клиентского кэша**: повторный клик на просмотренный модуль
  перезагружает документ с нуля.
- Документ материала читается PHP-сервером целиком (`$disk->get($file)`, режим `php`
  в раздатке) и пересылается как строка в `srcdoc` большого iframe — тяжёлые html
  (сканы РЭТ с inline-картинками) дают и медленный TTFB, и тяжёлый парсинг.
- Поиск по материалам (`SearchController::search`): синхронный обход всех `.html`
  файлов АУК через `Storage::disk('public')->files()` + `Str::contains` по содержимому
  каждого файла + `highlightWords` (DOM-разбор каждого совпадения) — O(N файлов) на
  каждый запрос, без индекса, без лимита времени, без пагинации. На АУК из 300 файлов
  это десятки секунд и 504 под нагрузкой. Плюс права: эндпоинт требует
  `content.manage|courses.manage`, обычный обучающийся поиск видеть не должен.
- После выбора результата поиска `loadContent()` по-прежнему живёт на
  `setTimeout(1000)` с прямой мутацией `iframeDoc.body.innerHTML` — гонка подсветки
  (первоисточник «подвисаний» оригинала, сохранился без изменений).
- Прокрутка: слушатель переведён на rAF (правильно), но каждое событие scroll всё
  равно трогает реактивные `canScrollUp/isScrolledToEnd`; при `frameHeight`-пересчётах
  это перерисовывает колонку с деревом. Дерево рендерится плоским списком из
  `aukstructures` (180+ узлов) с inline-стилями `nodeStyle(item)` на каждый узел —
  любое изменение состояния перерисовывает всё дерево.
- Раздача контента: конфиг по умолчанию — режим `php` (Laravel читает файл и отдаёт
  его body). При 20+ одновременных обучающихся PHP-FPM пул исчерпан, очередь растёт —
  «не справится при большой нагрузке» это ровно про это. `docs/content-delivery.md`
  описывает выход (`X-Accel-Redirect`), но он судя по всему не включён в проде.

## 2. План переделки плеера (по приоритету; P0 — убрать боль за дни)

### P0.1. Единый endpoint открытия курса (убрать 4 из 6 запросов старта)

Новый `GET /api/course-player/{course}` возвращает всё, что нужно плееру, одним
ответом и **компактным** видом:

```jsonc
{
  "course":   { "id", "title", "path", "aircraft_id", "aircraft_title" },
  "tree":     [ { "id", "parent_id", "type", "title" } ],      // БЕЗ links: link резолвится сервером в getlink
  "favorites":[ { "aukstructure_id", "title" } ],              // вместо отдельного getFavorites()
  "progress": { "visited": [], "last_file": "…" },             // серверный прогресс вместо localStorage-only
  "entry":    { "aukstructure_id", "signed_base", "expires" }  // сразу подписанный URL первого модуля
}
```

- Дерево — только поля, нужные UI (`select('id','parent_id','type','title')`).
- `entry` считает первый видимый модуль сервером → фронт не ждёт цепочку из 3 RTT,
  iframe стартует с подписанным src сразу.
- Убрать из `mounted()` все dispatch'и Vuex, кроме одного; удалить дубль
  `fetchAircrafts` и второй источник правды `/api/course?...`.

### P0.2. Кэш дерева и подписей на сервере

- `Cache::remember("player:{$courseId}:v{n}", 10min)` для дерева; инвалидация — счётчик
  версии bump'ится при реимпорте АУК (событие после `parsemanifest`).
- Подпись (`PrivateContentSigner`) — чистая функция от `aircraft|auk|expires`; TTL
  подписи поднять до 6ч для сессии чтения (окно чтения длиннее окна скачивания),
  кэш готового `signed_base` на уровне Redis по ключу пары.

### P0.3. Клиентский LRU-кэш документов материалов

- `Map<aukstructure_id, html>` на 10–15 последних документов (в пределах курса);
  повторный клик — мгновенный `srcdoc` без сети, с дозагрузкой в фоне (stale-while-revalidate).
- Prefetch следующего модуля того же раздела (`requestIdleCallback` → `getlink(next)`),
  чтобы «листание вперёд» было без задержки.

### P0.4. Раздача heavy-файлов — nginx, не php

- Включить `private_content.mode = nginx` + `X-Accel-Redirect` (гайд:
  `docs/nginx-x-accel-setup.md`, конфиг генерится `php artisan content:nginx-config`).
- Для srcdoc-режима это означает переход на `:src="signedUrl"` (+ postMessage-мостик
  для высоты кадра) либо `service worker`, кэширующий подписанные URL. Выбрать вариант
  «signed URL + sandbox allow-same-origin NO + мост» — см. P1.3.
- `sendfile on; open_file_cache max=10000 inactive=20m;` — обязательно (сотни мелких
  html/css/gif на АУК).

### P1.1. Индексированный поиск вместо обхода файловой системы

Текущая реализация непригодна ни под нагрузку, ни под UX (см. §1.2). Заменить:

1. Миграция таблицы `lesson_search_index (aukstructure_id, course_id, file, plain_text tsvector)`.
2. Наполнение — queued job при импорте/реимпорте АУК (`ImportCourseJob` уже существует
   как паттерн) + одноразовая команда `php artisan courses:index-content`.
3. `POST /api/search-files` → `websearch_to_tsquery('russian'|simple)` c `ts_headline`
   для подсветки, `limit 50`, пагинация; права — как у открытия курса
   (`CourseAccess::authorizeOpen`), а не `content.manage`, чтобы обучающиеся тоже могли искать.
4. Опционально позже: Meilisearch (Scout уже в зависимостях — `config/scout.php` есть).
5. Фронт: debounce 400 мс, skeleton-результаты, отмена предыдущего запроса (AbortController).

### P1.2. Переписать горячий путь `getlink()`

Сегодня ~7 запросов; свести к 2 (или использовать ответ P0.1 вообще без него при первом
открытии):

```php
$auk = Aukstructure::with('course.aircraft:id,path')->find($id);
CourseAccess::authorizeOpen($user, $auk->course);
$link = $auk->links()->value('link');            // fallback первого модуля — subquery, не ->get()->pluck()->first()
return [ /* те же поля */ + 'signed' => $signer->urlFor($aircraft, $auk, $link) ];
```

- Убрать мёртвые переменные `$url/$urlfirst`, исторические комментарии-«находки» — в git blame.
- `firstId` больше не нужен на этом эндпоинте: он считается один раз в P0.1.

### P1.3. Подсветка поиска без `setTimeout(1000)`

- Сервер (P1.1) возвращает `ts_headline` фрагменты — фронт подсвечивает их в списке
  результатов, а внутри iframe использует `URLFragmentTextDirective` (`#:~:text=`) или
  Text Fragments polyfill; отказ от прямой мутации `iframeDoc.body.innerHTML`
  (она ломает обработчики документа и вызывает reflow всего тела).
- Если нужна именно внутренняя подсветка — postMessage-мост в iframe с заранее
  внедрённым во время индексирования мини-скриптом (CSP-friendly), а не XPath-переписывание DOM.

### P1.4. Дерево курса — нормализовать и виртуализировать

- Бэк возвращает плоский массив с `parent_id` (уже так) → фронт строит дерево один раз
  (`useMemo`-подобный computed, WeakMap id→children).
- Компонент `CourseTree` (вынесен из монолита CourseManifest, см. план редизайна §8):
  рекурсивный `<template>`-компонент с раскрытием/сворачиванием тем и разделов,
  состоянием раскрытия в query (`?open=12,15`), отметками visited/прогресса.
- Для >300 узлов — `vue-virtual-scroller` (динамическая высота строк дерева).
- Inline-стили `nodeStyle(item)` заменить на CSS-классы `--level-1..3`
  (преимуущество: дерево перестаёт перерисовываться из-за смены активного узла).
- Переход от «плоского списка с отступом по type» к настоящей вложенной структуре —
  это одновременно и требование дизайна (рекурсивные таблицы/деревья,
  `docs/design-redesign-plan.md` Фаза 1.5), и perf-мера: скрытые ветви не рендерятся.

### P2. Архитектурные решения «на вырост»

| Решение | Зачем | Цена |
|---|---|---|
| SCORM-совместимый слой: читать `sequencing`/`objectives` из imsmanifest при импорте | сейчас из манифеста берут только дерево и ссылки; пройденные требования, блокировки ветвей недоступны | средняя; миграция `aukstructures` + fields |
| Хеш-именование путей материалов (`path_hash` уже было в оригинале!) + immutable cache-busting | подписанные URL становятся кэшируемыми CDN/браузером на год | низкая: схема уже заложена исторически |
| Отдельный read-only домен/поддомен для статики курсов (`content.example.internal`) за nginx | отвязать раздачу от Laravel полностью; сессия/Cookie не участвуют | ops-работа, конфиг в `nginx-x-accel-setup.md` рядом |
| Прогресс — событийная модель (`lesson_viewed` events → агрегат) вместо POST на каждый скролл-конец | снятие write-нагрузки с MySQL при массовом прохождении | средняя |
| Queue-импорт АУК (parsemanifest сегодня синхронный в HTTP-запросе `storeclasses`) | импорт архива на 500 файлов блокирует воркер на минуты | низкая: `ShouldQueue` |

## 4. Критерии приёмки (как измерить, что «перестало тормозить»)

1. **TTI страницы курса ≤ 1.2 с** на реальном АУК (≥150 узлов) на LAN: замер Playwright
   (`performance.getEntriesByType('navigation')` + первый кадр iframe).
2. Переключение между посещёнными модулями — **без сетевых запросов** (cache hit), ≤ 100 мс.
3. Поиск по 300-файловому АУК — **≤ 500 мс** p95, результаты paginated.
4. 50 одновременных читателей курса (k6/vegeta): p95 TTFB материалов ≤ 300 мс,
   PHP-FPM active < 20% пула (режим nginx).
5. Ни одного запроса `SELECT * FROM aukstructures ... links` без `select()`-списка в hot path.
6. Регрессионный Playwright-тест `course-player.spec.js`: открытие курса → клик модуля →
   srcdoc непустой → «вверх» появляется только при прокрутке → результат поиска открывает модуль.

## 5. Порядок работ (спринт-план)

- **Спринт 1 (P0):** player-endpoint + entry-подпись; LRU-кэш фронта; удаление дублей
  dispatch'ей; включение nginx-режима на staging; тесты TTI.
- **Спринт 2 (P1):** tsvector-поиск + миграция индекса + права; переписанный getlink;
  CourseTree с раскрытием (связан с Рекурсивной таблицей из дизайн-плана 1.5); отказ от setTimeout-подсветки.
- **Спринт 3 (P2):** очереди импорта, событийный прогресс, хеш-пути + immutable caching;
  решение по SCORM-sequencing (продуктовый вопрос владельцу курса).
