## Текущее состояние на октябрь 2026

План перечитан и сверен с кодом: каждый пункт выше помечен по результату проверки, а не по памяти. Расхождения были в обе стороны — план кое-где переоценивал сделанное, а где-то недооценивал.

**Что оказалось не сделано, хотя стояло галочка:**
- «рекомендованные курсы из каталога» и «топ-курсы / задачи на дашбордах» — данных для них в ответах API нет;
- pull-to-refresh на мобиле — не реализован.

**Что оказалось сделано, хотя галочки не стояло:**
- конструктор экзамена (`Exam/ExamWizard.vue`), календарь, геймификация, сертификаты, white-label, профиль — всё подключено к маршрутам.

Отдельно снят пункт «обложка-dropzone» в конструкторе курса: поля обложки нет в схеме, а форма без сохранения — это ровно тот антипаттерн, который документ предупреждает («редактор, который молча не сохранял бы изменения»).

**Остаток требует бэкенда, а не UI.** Чтобы закрыть эти пункты честно, нужно:
1. операция переупорядочивания узлов курса;
2. WYSIWYG-описание материала вместе с санитизацией и `sandbox` на `srcdoc`-iframe;
3. поля расписания курса и назначение группам в `courses` + `courseRules()`;
4. агрегаты «топ-курсы» и «работы на проверку» в сводке дашборда.

Проверено: `npm run build` (116 `.vue`), `npm test` (719 тестов, 60 файлов), `scripts/i18n_check.py`. Меню дополнительно проверено отдельно: все 35 `titleKey` из `navigation.js` разрешаются в обоих словарях.

## Проход 2026-10-19 (второй): проверка в браузере

Первые два прохода читались по коду. Этот — по работающему приложению:
поднята база (54 таблицы), выполнен вход, открыт курс из 77 разделов.
Большинство находок первых проходов подтвердились, но нашлась одна, которую
по коду увидеть было нельзя.

**Главная находка — экран курса был сломан целиком.** У `.cpl` стояло
`min-height`, а это не ограничивает рост, а задаёт нижнюю границу.
Боковая колонка разрасталась под дерево из 77 разделов: 5148px при окне
856px. Панель инструментов уезжала на 4765px и оказывалась за краем
экрана — кнопок «Поиск», «Избранное», «Дерево» не было видно вообще.
Прокручивался документ целиком вместо колонок по отдельности. Материал
при этом загружался корректно (14 КБ в iframe), но лежал в блоке, который
был виден как пустой.

Замеры до/после: `.cpl` 5249→760px, `.cm-toolbar` `top` 4765→228px,
`.cpl__sections` 4499→450px, высота документа 5249→856px.

**Вторая находка — редактор заметок вытеснял дерево.** Развёрнутые заметки
занимали 413px в колонке 697px, и список содержания схлопывался до 16px:
человек приходил на курс и не видел материалов. Инструменты перенесены в
новый слот `sidebar-top` (над деревом), заметки и избранное остались под
ним, сами заметки свёрнуты по умолчанию.

**Третья находка — опечатка в aria.** `aria-:label` вместо `aria-label`
в `CourseManifest.vue` и `UpdateCategory.vue`. Атрибут не применялся, и
панель инструментов не имела доступного имени.

Что подтвердилось и было исправлено ранее: цвета состояния на экзамене,
подсветка найденного, отсутствие панели инструментов, независимая
прокрутка колонок (проверена прокруткой обеих по очереди — документ
остаётся на `scrollTop: 0`).

Тёмная тема проверена отдельно: раскладка и цвета в порядке.

## Проход 2026-10-19 (третий): админские страницы

Продолжена проверка в браузере под администратором. Найдено две вещи:
одна — сломанный путь, вторая — неверные счётчики.

**Кнопка «Добавить пользователя» выкидывала из админки.** Она вела на
публичную регистрацию `/reg`, а после перезагрузки — на страницу входа.
Причина глубже, чем кнопка: `createUser` в `api/user.api.js` обслуживал
сразу два сценария, и оба ходили в `POST /api/register`. Это открытый
эндпоинт без прав администратора, где нельзя задать роль и группу.

Разделено на `registerUser` (публичная регистрация) и `createUser`
(`POST /api/v1/users`, право `users.create`). Форма `UserItemEdit.vue`
научилась создавать: в режиме создания добавились «Пароль» и «Роль».

**«Курсов 2 / Активных 4» на дашборде.** Счётчики считались по строкам
учебного плана, а не по курсам: в `group2learnings` у курса несколько строк
по `parent_id` (группа записана на конкретные материалы). Считается по
`groupBy('course_id')`. Заодно «Подходит к завершению» больше не печатает
один курс двумя карточками.

**`router.back()` после сохранения уводил не туда.** На форму можно попасть
прямым адресом, и истории не существует — `back()` возвращал на страницу
входа. Заменено на `router.push({ name: 'user.list' })`.

Проверено на живых данных: создание возвращает 201, роль применяется
(`instructor` в `users.role`), список перечитывается без ручного обновления.
Тестовые записи удалены.

## 2. Диагностика по слоям дизайна

### 2.1. Атомарный слой (токены, тема)

Что не так:
- Базовый кегль 14px и шкала до 24px — мало для «стильного» продукта: нет дисплейных размеров (hero, KPI-цифры), нет опен-тайпа/акцидентного шрифта для заголовков.
- Палитра «ведомственная»: один синий `#1a5fb4` + серые. Нет акцентного цвета для CTA/прогресса, нет градиентных/«свечения» приёмов для тёмной темы.
- Нет токенов анимации (`--dur-*`, `--ease-*`) — переходы задаются кто во что горазд или отсутствуют.
- Нет масштаба теней/элеваций для «слоистого» современного вида (glassmorphism-поверхности, мягкие многослойные тени).
- Радиусы только sm/md — современные продукты используют более крупные, «мягкие» радиусы карточек (12–16px) и pill-форму чипов/кнопок.

### 2.2. Компонентный слой

- `DataTable.vue` — собственная HTML-таблица без сортировки, multi-select строк, sticky-заголовка, density-режима (хотя `docs/ui-design.md` это обещает).
- Нет компонентов: stepper, tabs-форм, file-dropzone, rich-text-editor, code/diff-viewer, avatar-group, timeline, progress-ring, sparkline/charts, rating, calendar heatmap, kanban, command palette (⌘K), onboarding-tour.
- Поля форм: нигде нет `counter`/`maxlength`-индикаторов, маски ввода (ФИО, телефон, дата), каскадных selects, remote-search autocomplete, drag-and-drop reorder.
- Валидация фрагментирована: три стиля — `fieldErrors` вручную (CreateGroup), `:rules="[rules.required]"` (AddClass), vuelidate в одном месте (QuestionNew). Сообщение об ошибках — общий `v-alert` со списком вместо подсветки поля.

### 2.3. Слой страниц и потоков

- **Auth-экраны выглядят прототипом**: форма входа — серая карточка с синим тулбаром посреди пустой страницы; нет split-screen-брендинга, нет «Забыли пароль?», нет капча/2FA-UI.
- **Конструктор курса размазан** по четырём разным экранам (`RegisterCourse` → `UpdateCourse` → `AddClass` → `CourseManifest`) без общего степпера и без concept «черновик/превью/публикация».
- `CourseManifest.vue` (1165 строк) и `FileManager.vue` (1252 строки) — монолиты; в CourseManifest захардкожены цвета `#f5f5f5`, inline `fontSize: '20px'`.
- Маршруты-«вкладки» перегружены: `/datepicker`, `/upload-gift`, `/questions` vs `/questions-main` — мусор ранней разработки в навигации и URL.
- Иконки MDI вперемешку с FontAwesome (оба в зависимостях) — непоследовательный язык иконок.
- Локализация: `$t()` местами, но заголовки форм захардкожены по-русски («Добавление курса»).
- Нет page transitions, skeleton-загрузок на большинстве страниц (только прогресс-бар/спиннер).

### 2.4. Продуктовые дыры как «элементы дизайна»

Чего нет для полноценной LMS (нужны и UI, и backend):
1. Аналитика/отчёты (прогресс когорт,процент сдачи экзаменов, вовлечённость) — графики.
2. Сертификаты и их предпросмотр.
3. Редактор контента занятия (WYSIWYG + видео + файлы) — сейчас курс = манифест из структуры.
4. Геймификация: баллы, бейджи, streak-календарь.
5. Обсуждения/комментарии к урокам, Q&A с преподавателем.
6. Админ-настройки бренда (white-label: логотип, цвета, домен).
7. Назначения (assignments) с загрузкой работ и оценкой — отдельный тип «сложной формы».

## 3. Стратегия редизайна (принципы)

1. **Эволюция, не революция**: сохраняем токен-подход и Vuetify 3, расширяем систему; никаких параллельных UI-библиотек.
2. **Один визуальный язык**: все страницы мигрируют на каркас `PageHeader + u-card + DataTable/FormCard`; запрещаем `elevation-12`, инлайновые ширины и hex-цвета вне `tokens.css`.
3. **Формы — продукт внутри продукта**: единый фреймворк (схема → компонент → валидация → состояния), сложные формы = stepper + conditional + repeatable + upload.
4. **Каждый экран имеет 4 состояния**: loading (skeleton), empty, error (retry), success — по уже написанному `docs/ui-design.md`, но теперь реально.
5. **Стильность = детали**: motion (150–250ms, ease-out), micro-interactions, layered shadows, larger radii, accent-цвет для данных/прогресса, аккуратная типографическая иерархия, тёмная тема как first-class.

## 8. Проверка плана по факту (октябрь 2026)

План перечитан и сверен с кодом: каждый пункт выше помечен по результату
проверки, а не по памяти. Расхождения были в обе стороны — план кое-где
**переоценивал** сделанное, а где-то **недооценивал**.

Что оказалось не сделано, хотя стояло галочка:
- «рекомендованные курсы из каталога» и «топ-курсы / задачи на дашбордах» —
  данных для них в ответах API нет;
- pull-to-refresh на мобиле — не реализован.

Что оказалось сделано, хотя галочки не стояло:
- конструктор экзамена (`Exam/ExamWizard.vue`), календарь, геймификация,
  сертификаты, white-label, профиль — всё подключено к маршрутам.

Отдельно снят пункт «обложка-dropzone» в конструкторе курса: поля обложки
нет в схеме, а форма без сохранения — это ровно тот антипаттерн, который
документ предупреждает («редактор, который молча не сохранял бы изменения»).

**Остаток требует бэкенда, а не UI.** Чтобы закрыть эти пункты честно,
нужно: (1) операция переупорядочивания узлов курса; (2) WYSIWYG-описание
материала вместе с санитизацией и `sandbox` на `srcdoc`-iframe;
(3) поля расписания курса и назначения группам в `courses` + `courseRules()`;
(4) агрегаты «топ-курсы» и «работы на проверку» в сводке дашборда.

Проверено: `npm run build` (116 `.vue`), `npm test` (719 тестов, 60 файлов),
`scripts/i18n_check.py`. Меню дополнительно проверено отдельно: все 35
`titleKey` из `navigation.js` разрешаются в обоих словарях — штатный
`i18n_check.py` сканирует только `Pages/` и `components/`, а `navigation.js`
лежит в корне `js/` и его не видит.
