# План редизайна LMS: стильный интерфейс, сложные формы, полноценная платформа

> Анализ выполнен по состоянию репозитория (Laravel + Vue 3 + Vuetify 3 + PostgreSQL).
> Изменения **не вносились** — это дорожная карта.

---

## 1. Текущее состояние: что уже хорошо

Перед планом — честная инвентаризация сильных сторон, чтобы их не сломать:

| Актив | Где | Почему ценно |
|---|---|---|
| Дизайн-токены (цвет, типографика, отступы, радиусы, тени) | `resources/css/tokens.css` | Единый источник правды; Vuetify-тема читает те же значения (`resources/js/Vuetify/index.js`) |
| Светлая/тёмная тема + переключатель | `ThemeToggle.vue`, tokens под `.v-theme--dark` | Редкость для внутренних LMS — надо развивать, а не выбрасывать |
| UI-примитивы | `components/ui/`: `FormCard`, `DataTable`, `EmptyState`, `PageHeader`, `Breadcrumbs`, `ConfirmDialog`, `ToastStack`, `GlobalSearch`, `NotificationBell` | Каркас дизайн-системы уже заложен |
| Навигация на основе прав | `navigation.js` + `utils/routePermissions`, `v-can` | RBAC-меню — уровень «серьёзного» приложения |
| Ролевые дашборды | `Dashboard/{Trainee,Manager,Role}Dashboard.vue` | Правильная идея разделения по ролям |
| Функциональная база | Экзамены, AI-тьютор, файловый менеджер с chunk-upload, каталог, календарь, группы, рубрикатор оценок | Фундамент полноценной LMS уже есть |

**Проблема №1:** проект живёт в двух эпохах дизайна. Часть страниц (`Courses.vue`, `ExamRunner.vue`) сделана на новой системе `u-*`-классов, а ~9 ключевых страниц (`Login`, `Register`, `RegisterCourse`, `UpdateCourse`, `AddClass`, `CourseItem`, `ExamineItem`, `GroupLearning`, `UserChpass`) — это наследие v2: `elevation-12`, синие `v-toolbar` внутри карточек, фиксированные `style="width:600px"`.

**Проблема №2:** для «полноценной LMS» не хватает целых продуктовых доменов (отчёты, сертификаты, контент-редактор, геймификация) и единого подхода к формам.

## 2. Диагностика по слоям дизайна

### 2.1. Атомарный слой (токены, тема)

Что не так:
- Базовый кегль 14px и шкала до 24px — мало для «стильного» продукта: нет дисплейных размеров (hero, KPI-цифры), нет опен-тайпа/акцидентного шрифта для заголовков.
- Палитра «ведомственная»: один синий `#1a5fb4` + серые. Нет акцентного цвета для CTA/прогресса, нет градиентных/«свечения» приёмов для тёмной темы.
- Нет токенов анимации (`--dur-*`, `--ease-*`) — переходы задаются кто во что горазд или отсутствуют.
- Нет масштаба теней/элеваций для «слоистого» современного вида (glassmorphism-поверхности, мягкие многослойные тени).
- Радиусы только sm/md — современные продукты используют более крупные, «мягкие» радиусы карточек (12–16px) и pill-форму чипов/кнопок.

### 2.2. Компонентный слой

- `DataTable.vue` — собственная HTML-таблица без сортировки, multi-select строк, sticky-заголовка, density-режима (хотя `docs/ui-design.md` это обещает).
- Нет компонентов: stepper, tabs-форм, file-dropzone, rich-text-editor, code/diff-viewer, avatar-group, timeline, progress-ring, sparkline/charts, rating, calendar heatmap, kanban, command palette (⌘K), onboarding-tour.
- Поля форм: нигде нет `counter`/`maxlength`-индикаторов, маски ввода (ФИО, телефон, дата), каскадных selects, remote-search autocomplete, drag-and-drop reorder.
- Валидация фрагментирована: три стиля — `fieldErrors` вручную (CreateGroup), `:rules="[rules.required]"` (AddClass), vuelidate в одном месте (QuestionNew). Сообщение об ошибках — общий `v-alert` со списком вместо подсветки поля.

### 2.3. Слой страниц и потоков

- **Auth-экраны выглядят прототипом**: форма входа — серая карточка с синим тулбаром посреди пустой страницы; нет split-screen-брендинга, нет «Забыли пароль?», нет капча/2FA-UI.
- **Конструктор курса размазан** по четырём разным экранам (`RegisterCourse` → `UpdateCourse` → `AddClass` → `CourseManifest`) без общего степпера и без concept «черновик/превью/публикация».
- `CourseManifest.vue` (1165 строк) и `FileManager.vue` (1252 строки) — монолиты; в CourseManifest захардкожены цвета `#f5f5f5`, inline `fontSize: '20px'`.
- Маршруты-«вкладки» перегружены: `/datepicker`, `/upload-gift`, `/questions` vs `/questions-main` — мусор ранней разработки в навигации и URL.
- Иконки MDI вперемешку с FontAwesome (оба в зависимостях) — непоследовательный язык иконок.
- Локализация: `$t()` местами, но заголовки форм захардкожены по-русски («Добавление курса»).
- Нет page transitions, skeleton-загрузок на большинстве страниц (только прогресс-бар/спиннер).

### 2.4. Продуктовые дыры как «элементы дизайна»

Чего нет для полноценной LMS (нужны и UI, и backend):
1. Аналитика/отчёты (прогресс когорт,процент сдачи экзаменов, вовлечённость) — графики.
2. Сертификаты и их предпросмотр.
3. Редактор контента занятия (WYSIWYG + видео + файлы) — сейчас курс = манифест из структуры.
4. Геймификация: баллы, бейджи, streak-календарь.
5. Обсуждения/комментарии к урокам, Q&A с преподавателем.
6. Админ-настройки бренда (white-label: логотип, цвета, домен).
7. Назначения (assignments) с загрузкой работ и оценкой — отдельный тип «сложной формы».

## 3. Стратегия редизайна (принципы)

1. **Эволюция, не революция**: сохраняем токен-подход и Vuetify 3, расширяем систему; никаких параллельных UI-библиотек.
2. **Один визуальный язык**: все страницы мигрируют на каркас `PageHeader + u-card + DataTable/FormCard`; запрещаем `elevation-12`, инлайновые ширины и hex-цвета вне `tokens.css`.
3. **Формы — продукт внутри продукта**: единый фреймворк (схема → компонент → валидация → состояния), сложные формы = stepper + conditional + repeatable + upload.
4. **Каждый экран имеет 4 состояния**: loading (skeleton), empty, error (retry), success — по уже написанному `docs/ui-design.md`, но теперь реально.
5. **Стильность = детали**: motion (150–250ms, ease-out), micro-interactions, layered shadows, larger radii, accent-цвет для данных/прогресса, аккуратная типографическая иерархия, тёмная тема как first-class.

## Фаза 4 — Новые продуктовые модули (3–5 недель, частично backend)

Порядок по ценности для «полноценной LMS»:

1. **Отчёты и аналитика** (`/reports`)
   - UI: конструктор отчёта = сложная форма-фильтр (период, группа, курс, метрики) + таблица + графики + экспорт XLSX/PDF.
   - Backend: агрегаты по `exam_attempts`, `group2learnings`, прогресс уроков.
2. **Назначения (Assignments)** — домашние работы: загрузка файлов dropzone, дедлайн, оценка препода (форма с rubric-шкалой), статусы student/teacher.
3. **Сертификаты**: шаблон с превью в реальном времени (форма настройки: вуз/логотип/подписи), генерация PDF, верификация по номеру.
4. **Геймификация**: XP, бейджи (галерея), лидерборд группы, streak — подаётся компактно, без «детскости».
5. **Коммуникации**: комментарии/вопросы под уроком, ответы преподавателя, упоминания (уведомления уже есть — расширить типы).
6. **White-label настройки**: бренд-панель (логотип-dropzone, выбор primary/accent из color-picker → перезапись CSS-переменных на лету, превью light/dark).
7. **Профиль студента/преподавателя**: публичная страница инструктора в каталоге, портфолио курсов, рейтинг.

## 5. Что убрать (сокращение шума)

| Убрать | Где | Причина |
|---|---|---|
| `elevation-12` + `v-toolbar` внутри карточек форм | 9 страниц (Login, Register, RegisterCourse, UpdateCourse, AddClass, CourseItem, ExamineItem, GroupLearning, UserChpass) | Визуально — Material 2019 года, конфликтует с flat-системой `u-card` |
| Инлайновые ширины `style="width:600px"` | те же страницы | Ломает адаптив; ширина = класс `--w-form-*` |
| Hardcode-цвета (`#f5f5f5` и др.) | `CourseManifest.vue` и ещё ~8 файлов | Обходят токены, темнеют неправильно |
| FontAwesome целиком | package.json | Дублирование с MDI, непоследовательные иконки |
| Мёртвые/тестовые маршруты | `/datepicker`, `/upload-gift` (как пункт меню), `/test/*`, закоментированные `/auk/*` | Мусор в навигации подрывает «серьёзность» |
| `merged_all.txt`, `index.html` в корне (если это артефакт), `languagepacks.json` (пустой `[2]`) | корень repo | Не относятся к продукту, путают |
| Общий `v-alert` со списком ошибок вместо подсветки полей | многие формы | Антипаттерн UX |
| Булевы подписи в UI («Показать: true») | остатки | Уже исправлено в Courses — найти остальные |

## 6. Что добавить (сводно)

**Дизайн-система:** скелетоны, stepper/wizard, tabs-формы, dropzone, charts-kit, command palette, tour, brand-panel, avatar-group, timeline, rating, heatmap, styleguide-страница.

**Формы:** схемная валидация (zod/vee-validate), маски, счётчики, autosize, каскады, remote-search, repeatable+DnD, dirty-guard, автосейв черновиков, async-правила уникальности.

**Экраны:** split-auth + forgot-password/2FA, курс-плеер с прогрессом, results-review экзамена, reports-конструктор, assignments, сертификаты, геймификация, комментарии, мобильная bottom-nav, collapsed rail.

## 7. Ожидаемый эффект и порядок работ

```
Неделя 1        : Фаза 0 + старт токенов
Недели 2–3      : Дизайн-система 2.0 + framework форм
Недели 4–6      : Auth + дашборды + wizard курса (демо-критично)
Недели 7–8      : Course player, экзамены, таблицы, каталог
Недели 9–12     : Отчёты, назначения, сертификаты (backend+UI)
Фон             : полировка, a11y, i18n, e2e
```

Приоритет «вау-эффекта» для пользователя: **auth-экраны → дашборд → конструктор курса → плеер курса**. Приоритет «полноценной LMS»: **отчёты → назначения → сертификаты**.
