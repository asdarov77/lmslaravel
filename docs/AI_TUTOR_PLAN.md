# Режим «Тренажёр» — локальная нейросеть для самоподготовки по материалам курсов

Версия: 0.1.0 (план, код пока не написан)
Статус: proposal

## 1. Идея и жёсткие границы

- **Тренажёр (AI)** — отдельное окно/страница «Самоподготовка». Локальная LLM на CPU
  генерирует вопросы **строго по материалам курса** пользователя (по его специальности,
  определяемой через Category/Course как в GiftParser). Пользователь отвечает, получает
  обратную связь. Вопросы каждый раз новые, с нарастающим контекстом. **Не влияет на оценки.**
- **Экзамен (без AI)** — остаётся как есть: `Exam` + импортированный банк вопросов (GIFT),
  серверная проверка, `exam_attempts`. Тренажёр никогда не подменяет экзаменационные вопросы.

Принцип «без самодеятельности»: модель не знает тему — она только переформулирует
вопросы из переданного ей фрагмента текста. Всё, что вне фрагмента, — запретить и отбрасывать.

## 2. Какая нейросеть (CPU-only, локально)

Рекомендуемая связка: **Ollama + llama.cpp (GGUF, квантование Q4_K_M)**.

| Модель | Размер | RAM | Скорость на CPU | Назначение |
|---|---|---|---|---|
| **Qwen2.5-3B-Instruct** (основная рекомендация) | ~2 GB | ~4–6 GB | приемлема (8+ ядер) | русский + строгий JSON-following |
| Phi-3.5-mini (3.8B) | ~2.3 GB | ~4–6 GB | хорошо | англоцентричные курсы |
| Gemma-2-2b-it | ~1.6 GB | ~4 GB | быстро | слабее в русском |
| Qwen2.5-7B-Instruct (опция для мощных ПК) | ~4.7 GB | ~8–10 GB | медленно, но качество выше | сложные тексты |

- Оллама ставится одним бинарником на машину пользователя/локальный сервер,
  API — HTTP `http://127.0.0.1:11434/api/generate` (OpenAI-совместимый `/v1`).
- Температуру ставить низкой (0.3–0.7): нужна вариативность вопросов, но не выдумки.
- Для эмбеддингов (поиск релевантных фрагментов): **bge-m3** или **multilingual-e5-small**
  через тот же Ollama — тоже CPU.

## 3. Архитектура (вписывается в текущий Laravel + Vue + PostgreSQL)

```
Vue (окно "Самоподготовка")            Laravel (LMS)                 Ollama (localhost)
        |  POST /api/v1/tutor/session      |                              |
        |--------------------------------->| выбирает материал по спец.   |
        |                                  | режет на чанки, top-k by     |
        |                                  | relevance (эмбеддинги)       |
        |                                  |---- prompt (чанк+задания)-->|
        |                                  |<--- JSON {questions:[...]}---|
        |                                  | валидация схемы, grounding- |
        |                                  | проверка, дедуп по сессии   |
        |<-- вопросы (без "правильного     | сохранение в tutor_*        |
        |    варианта" для открыт. типов)  |                             |
        |-- ответы ----------------------->| эталонный ответ + оценка    |
        |                                  | от LLM (по чанку), фидбек   |
```

Laravel выступает «дирижёром»: промпты, валидация, хранение истории. Браузер
напрямую к Ollama не ходит (CORS/токены/контроль промпта).

### Защита от «самодеятельности» (ключевое)

1. **Grounding**: в системном промпте — «используй ТОЛЬКО приведённый фрагмент;
   если вопрос нельзя составить — верни пустой массив». Ответ модели парсится как JSON
   по жёсткой схеме; всё, что не распарсилось — отброс и повтор.
2. **Проверка возврата (back-check)**: сгенерированный вопрос отправляется обратно
   модели с заданием «найди в фрагменте предложение-подтверждение». Нет подтверждения —
   вопрос бракуется. (Дорого — включать опционально, настройка per-course.)
3. **Дедупликация**: нормализация + сравнение эмбеддингов вопроса с уже заданными
   в рамках пользователя по материалу (окно N последних) — иначе «каждый раз разные».
4. **Ответы проверяются по эталону**: при генерации сразу просим `reference_answer`
   с цитатой из фрагмента; open-ended ответ пользователя оценивается моделью против
   эталона + цитаты (не «по знаниям модели»).
5. Никаких внешних API — весь трафик в пределах машины/локальной сети.

## 4. Схема БД (новые миграции)

```sql
tutor_materials   (id, course_id, category_id NULLABLE /*специальность*/, file_id NULLABLE,
                   title, source /* upload|lyx|gift-context */, status /* pending|indexed|failed */)
tutor_chunks      (id, material_id, seq, content TEXT, token_count INT,
                   embedding VECTOR(1024) NULLABLE)   -- pgvector; без него — LIKE/tsvector fallback
tutor_sessions    (id, user_id, material_id, created_at, finished_at, context_window JSONB)
tutor_items       (id, session_id, chunk_id, qtype /* mcq|short|open */, question TEXT,
                   options JSONB NULLABLE, reference_answer TEXT, source_quote TEXT,
                   asked_count INT DEFAULT 0 /* для вариативности: реже повторять то же */ )
tutor_responses   (id, item_id, user_id, answer TEXT, verdict /* correct|partial|wrong */,
                   feedback TEXT, auto_score REAL NULLABLE, llm_meta JSONB)
```

Права (RBAC, существующая система `permission:` middleware):
- `tutor.use` — обучаемый, тренажёр по своим назначенным курсам (через Group2learning);
- `tutor.manage` — админ: индексация материалов,проверка качества промптов.

## 5. API (routes/api.php, конверт `{success,data,error,meta}` как принято)

| Метод | Путь | Описание |
|---|---|---|
| POST | `/api/v1/tutor/sessions` | начать сессию: `{material_id|course_id, count, types[]}` |
| GET  | `/api/v1/tutor/sessions/{id}/next-question` | следующий вопрос (сервер выбирает чанк, расширяя контекст) |
| POST | `/api/v1/tutor/items/{item}/answer` | ответ → серверная проверка → `{verdict, feedback, reference_answer, source_quote}` |
| GET  | `/api/v1/tutor/stats` | прогресс тренажёра (отдельно от exam_attempts!) |
| POST | `/api/v1/admin/tutor/materials/index` | (tutor.manage) запустить индексацию файла/курса |

Генерация асинхронная (queued job): на CPU 3B модель даёт 5 вопросов за 20–60 с —
UI показывает статус, батчи кэшируются в `tutor_items` (генерируем с запасом, напр. пачку 10).

## 6. Frontend (Vue 3 + Vuetify)

- `resources/js/Pages/Tutor/TutorMain.vue` — выбор курса/материала, кнопка «Начать тренинг»,
  история и статистика тренажёра.
- `resources/js/Pages/Tutor/TutorRunner.vue` — карточка вопроса (аналогично `ExamRunner.vue`,
  но: без таймера, без баллов в зачёт, кнопки «Показать эталон»/«Подсказка из текста»,
  режимы: тест / короткий ответ / открытый ответ с оценкой).
- Отдельное окно: роут `/tutor` открывается через `window.open` или полноэкранный dialog —
  как удобно; состояние сессии живёт на сервере, окно можно закрыть и продолжить.

`.env`:

## 8. Поэтапный план (каждый этап — рабочий инкремент)

**Этап 0 — PoC (1–2 дня).** Python/PHP скрипт: берём 1 текст курса, промпт, Ollama
`qwen2.5:3b`, получаем JSON-вопросы. Критерий: ≥7/10 вопросов пригодны, 0 выдуманных фактов.

**Этап 1 — Индексация материалов (2–3 дня).** Миграции `tutor_materials/tutor_chunks`;
извлечение текста: PDF/DOCX (phpoffice уже есть; PDF — внешний конвертер или очередь),
LYX-материалы через существующий `app/Lyx`, файлы курсов (`File`, FilesController).
Чанки 800–1200 токенов с перекрытием. Эмбеддинги: pgvector + Ollama embed; fallback — Postgres FTS.

**Этап 2 — Генерация + тренажёр MVP (3–5 дней).** Jobs-генерация, схема-валидация JSON,
дедуп, API из §5, страницы TutorMain/TutorRunner. Типы вопросов: MCQ + короткий ответ.
Флаг `TUTOR_ENABLED`, права `tutor.use/manage`.

**Этап 3 — Контроль качества (2–3 дня).** Back-check grounding, оценка открытых ответов по эталону,
статистика тренажёра, «нарастающий контекст» (сессия помнит затронутые чанки и избегает повторов;
чем длиннее сессия — тем шире окно чанков).

**Этап 4 — Экспорт в банк (опционально, 1–2 дня).** Кнопка `tutor.manage`: понравившиеся
AI-вопросы после ручной проверки методистом → в `Question`/GIFT-банк. Только так AI-вопросы
могут попасть на экзамен — через человека.

**Этап 5 — Упаковка для пользователя.** Инструкция/инсталлятор: Ollama + `ollama pull qwen2.5:3b-instruct`,
автостарт службой; в LMS — экран диагностики «нейродвижок доступен?» (ping `/api/tags`).

## 9. Риски и ограничения

- **Скорость CPU**: 3B Q4 ≈ 5–15 ток/с на 8 ядрах → генерация пачкой в фоне, не в момент клика.
- **Галлюцинации**: снижаются grounding-промптом + back-check + эталонными ответами;
  полностью не устраняются — поэтому тренажёр отделён от экзамена.
- **Качество русского**: qwen2.5:3b приемлемо; если курсы англоязычные — phi3.5.
- **PDF с картинками/сканами** — нужен OCR (вне объёма первых этапов, помечать material как failed).
- **Лицензии моделей**: все перечисленные — свободные (Apache-2.0/MIT/QWEN license), локальное
  использование легально.

## 10. Что остаётся неприкосновенным

Итоговая аттестация: `exams`, `exams/{exam}/questions`, `submit` — импортированный банк,
серверная проверка, права. Тренажёр пишет только в `tutor_*` таблицы и никогда
не создаёт `exam_attempts`.
