# Заметка по раздаче материалов: состояние на 2026-10-07

Рабочая заметка о том, как устроена и проверена выдача материалов курсов,
что настроено локально и какие три ошибки стоили больше всего времени.
Не замена `docs/content-delivery.md` (там устройство и защита), а запись о
том, что реально запущено и проверено.

## Коротко

Два режима, переключаются галкой «Настройки → Раздача материалов»:

| Режим | Что делает | Когда применять |
|---|---|---|
| `php` | Контроллер читает файл и отдаёт потоком | Всегда работает, ничего не требует |
| `nginx` | Контроллер проверяет подпись и отвечает пустым телом с `X-Accel-Redirect`, файл отдаёт nginx | Под нагрузкой: ни одного занятого PHP-воркера |

Значение хранится в `settings.content_delivery`. По умолчанию (`config/private_content.php`)
— `php`, и это правильный дефолт: режим `nginx` без настроенного `location`
ломает выдачу целиком.

## Что настроено локально

Системный nginx поставить не удалось: `sudo` требует пароль. Для проверки
использован переносимый nginx 1.22.1:

```
/tmp/opencode/nginx-portable/root/usr/sbin/nginx
/tmp/opencode/nginx-portable/nginx.conf
```

Запуск и проверка:

```bash
php artisan content:nginx-config                 # посмотреть фрагмент
nginx -p /tmp/opencode/nginx-portable \
      -c /tmp/opencode/nginx-portable/nginx.conf
php artisan serve --host=127.0.0.1 --port=8000   # приложение
```

Порядок важен: сначала nginx, потом приложение — иначе первые запросы
упадут на `connection refused`.

Текущее состояние локальной БД: `content_delivery = nginx`.
Приложение на `:8000`, nginx на `:8081`.

## Проверено на живых запросах

| Проверка | Ожидалось | Факт |
|---|---|---|
| Подписанный URL через nginx | 200 + тело, отдал nginx | 200, 11 061 байт, `X-Protected-Delivery: nginx` |
| Прямой запрос `/_protected-content/...` | 404 | 404 |
| Обход через `/storage/app/public/private/...` | 404 | 404 |
| Подменённая подпись | 403 | 403 |
| Истёкший срок подписи | 403 | 403 |
| Валидная подпись, несуществующий файл | 404 | 404 |
| Режим `nginx`, но запрос мимо nginx | файл через PHP | 200 с телом |

## Три ошибки, которые стоили времени

### 1. Режим `nginx` без nginx на переднем плане → пустое тело со статусом 200

Приложение часто запускают без nginx: `php artisan serve`, тесты,
artisan-команды. Там `X-Accel-Redirect` никто не обрабатывает, и Symfony
отдаёт наружу пустой ответ со статусом **200** — материал выглядит как
пустая страница, и в логе нет ни ошибки, ни предупреждения.

Решение: `ContentDelivery::isAccel()` включает X-Accel только если видит
заголовок-метку `X-Lms-Accel` с правильным значением (выводится из
`APP_KEY`, поэтому клиент его не подделает). Без метки приложение
отдаёт файл само. Значение метки кладёт в конфиг nginx команда
`content:nginx-config`.

### 2. Alias в сгенерированном конфиге указывал на уровень выше

`X-Accel-Redirect` собирается из относительного пути **без** префикса
`private/`. Генератор подставлял `alias` от корня диска
(`storage/app/public`), и nginx искал `storage/app/public/<самолёт>/...`
вместо `storage/app/public/private/<самолёт>/...` — 404 на каждый
материал, при этом подпись, `internal` и проверки прав проходили.

Правильный alias — от `config('filesystems.disks.private.root')` плюс
`PrivateContent::PREFIX`. Оба расхождения закрыты тестами в
`tests/Feature/ContentDeliveryTest.php`.

### 3. Приватный каталог лежит внутри публичной части storage

`storage/app/public/private/` — внутри публичной папки. Симлинки
`public/storage` сейчас нет, но `php artisan storage:link` (обычный шаг
деплоя) создаст `public/storage -> storage/app/public`, и весь материал
станет доступен по `/storage/private/...` **без проверки подписи**.

Закрыто явно в конфиге nginx (`location ^~ /storage { return 404; }`),
плюс `visibility => private` и команда `php artisan content:check-exposure`.

## Чего делать не надо

* **`secure_link` в nginx не добавлять.** Подпись намеренно лежит в пути,
  чтобы её наследовали относительные ссылки внутри курса (CSS, JS, картинки).
  `secure_link` требует отдельного токена на каждый ресурс и ломает
  отрисовку материала.
* **Не убирать импорт метаданных при включённом nginx.** В БД остаются
  курсы, модули, специальности, связи — на них держатся каталог, поиск и
  проверки прав. Меняется только то, кто отдаёт байты файла.
* **Не переносить `storage/app/public/private`** без отдельного решения:
  это 7000+ файлов, и на них завязаны `aircrafts.path`, импорт и конфиг nginx.

## Что осталось на боевой машине

1. Установить системный nginx и положить фрагмент внутрь `server`-блока,
   который проксирует или `fastcgi_pass`-ит на приложение. Отдельным
   `server`/`location` он не сработает.
2. Взять значение метки из `php artisan content:nginx-config` и подставить
   его в `proxy_set_header X-Lms-Accel` (в репозитории оно лежать не должно).
3. Проверить `nginx -t && systemctl reload nginx`.
4. `php artisan content:check-exposure`.
5. Открыть подписанный URL: 200 с пустым телом и заголовком
   `X-Accel-Redirect`; затем `php artisan content:nginx-config`-сгенерированный
   фрагмент должен отдать сам файл.
6. Откат — одна галка обратно в «php». Код старого режима не удалён.
