# Тренажёр: локальная генерация вопросов по материалам курсов

## Граница, которую держит модуль

Тренажёр **не влияет на оценки**. Итоговая аттестация остаётся на
импортированном банке GIFT с серверной проверкой. Тренажёр пишет только в
таблицы `tutor_*` и никогда не создаёт `exam_attempts`.

Это не договорённость, а код и тесты: `tests/Feature/TutorApiTest.php`
проверяет, что ответ в тренажёре не меняет число `exam_attempts` и не
добавляет вопросов в банк, а `tutor.stats` не считает попытки экзаменов.

Причина жёсткая: галлюцинации нельзя устранить полностью, и модель,
ошибающаяся в фактах, не должна влиять на результат. Разделение
контуров делает ошибку модели безобидной.

## Как устроено

```
Vue (окно «Самоподготовка»)        Laravel                     Ollama / сателлит
  │                                  │                              │
  │ POST /api/v1/tutor/sessions      │ ставит задачу в очередь        │
  │─────────────────────────────────>│                              │
  │<─ {generating: true} мгновенно   │                              │
  │                                  │ GenerateTutorQuestions        │
  │ GET .../sessions/{id}  (опрос)   │ выбор фрагментов по поиску     │
  │─────────────────────────────────>│──── prompt (фрагмент) ───────>│
  │                                  │<─── JSON вопросов ─────────────│
  │                                  │ проверка схемы и опоры на текст│
  │<─ вопрос (без эталона)           │ дедупликация, запись в tutor_*│
  │── ответ ────────────────────────>│ сверка с эталоном + цитатой    │
```

Laravel — дирижёр: промпты, проверки, права, прогресс. Браузер к Ollama
не ходит.

## Защита от «самодеятельности»

Модель не знает тему — она переформулирует вопросы из переданного
фрагмента. Проверок четыре, и три из них детерминированные, то есть не
могут соврать.

1. **Цитата обязана находиться во фрагменте.** Модель приводит
   `source_quote`; проверка ищет её в тексте. Допуск — все значимые слова
   цитаты встречаются во фрагменте (модель переставляет слова, но не
   выдумывает). Подмена факта не проходит: в примере ниже «250 А» не
   встречается в тексте.

   ```
   честная цитата                       → найдена
   «более 100 А» → «более 250 А»        → отклонена
   «раз в 3 месяца» (в тексте 6 месяцев) → отклонена
   ```

2. **Ответ должен подтверждаться цитатой.** Эталон обязан содержаться в
   подтверждении. Эта проверка выросла из замеров: `qwen2.5:1.5b` задавала
   вопрос «Где находится гидросистема №1?» с ответом «правой двери» —
   цитата настоящая, но по ней наоборот.

3. **Дедупликация по нормализованному тексту.** Отпечаток строится без
   знаков препинания и регистра, поэтому перестановка запятой не даёт
   «нового» вопроса.

4. **Back-check** (выключен по умолчанию, см. ниже) — вопрос
   возвращается модели с заданием найти подтверждение.

Формально это система с тремя уровнями отказоустойчивости: лучший
вопрос отклоняется, а не показывается. Цена — часть выдачи теряется, и
её размер нужно измерять, а не угадывать.

## Модель: почему 3B — это минимум

Требование — работа на CPU, поэтому размер модели ограничивает память и
скорость. Замеры на реальном материале курса (`php artisan tutor:quality`):

| Модель | Размер | Результат |
|---|---|---|
| `qwen2.5:0.5b-instruct` | 397 МБ | 0 пригодных: JSON не выдерживает, цитаты выдумывает |
| `qwen2.5:1.5b-instruct` | 986 МБ | 0 пригодных: смыслово неверные вопросы с настоящей цитатой |
| `qwen2.5:3b-instruct` | 1.9 ГБ | пригодные вопросы, качество ниже |
| **`qwen3:4b`** | **2.5 ГБ** | **дефолт, ~67% пригодных, ~12 с на фрагмент** |
| `qwen3:8b` | 5.2 ГБ | выше качество, заметно медленнее |

Дефолт — `qwen3:4b`: это минимальный размер, при котором тренажёр даёт
пригодные вопросы, и вчетверо легче `qwen3.5:9b-q4_K_M` (6.6 ГБ).

### thinking обязательно выключён

У `qwen3.*` размышление включено по умолчанию и съедает весь бюджет
токенов. Замер на `qwen3.5:9b`: **96 секунд и пустой ответ** против **3
секунд и нормального ответа** с `think: false`. Поэтому `think: false`
передаётся явно, и `TUTOR_DISABLE_THINKING` выключать нельзя.

## Что реально ускоряет генерацию

| Рычаг | Эффект |
|---|---|
| Батч вопросов за вызов | 3 вопроса — 5.6 с на принятый, 5 вопросов — 2.2 с. Промпт отправляется один раз |
| `TUTOR_MAX_TOKENS=700` | 1200 означали, что модель думает там, где хватит сотни токенов |
| `TUTOR_MAX_CHUNKS_PER_JOB=4` | без предела задача обходила сотни фрагментов и висела десятками минут |
| Back-check выключен | убирает целый дополнительный вызов **на каждый** вопрос |

### Про back-check и расхождение с планом

План предлагает `TUTOR_BACKCHECK=true`. По умолчанию выключено, и это
осознанное отклонение: на 3–4B он стоит вдвое дороже и на слабой модели
даёт шум вместо пользы — модель пересказывает подтверждение, оно не
находится дословно, и результат становится случайным.

Основную защиту теперь несут проверки 1 и 2, которые бесплатны. Включать
back-check стоит на сильной модели (7B+), где пересказ редок:

```
TUTOR_BACKCHECK=true
```

## Поиск фрагментов: два бэкенда

| | Вариант A (сателлит) | Вариант B (по умолчанию) |
|---|---|---|
| Хранилище | ChromaDB, коллекция на курс | `tsvector` в Postgres |
| Требует | Python + `chromadb` + `sentence-transformers` | ничего |
| Поиск | по смыслу | по словам |
| Включение | `TUTOR_SATELLITE_URL=http://127.0.0.1:8100` | пусто |

Сателлит нужен потому, что на машине пользователя нет `pgvector`, а
ставить расширение Postgres — отдельная задача администрирования.

Права доступа **не** раздаются сателлитом: Laravel передаёт уже
проверенный `material_id`, а сателлит отвечает только за поиск по тексту.
Коллекция создаётся на курс, а не на пользователя.

Любой сбой сателлита (не запущен, нет ChromaDB, таймаут) оставляет
тренажёр работоспособным на полнотекстовом поиске — иначе одна
неустановленная Python-зависимость выключала бы всю функцию.

### Русский полнотекстовый поиск без словаря

Словарь `simple`, а не `russian`: в материалах полно аббревиатур (ПП-5,
АСУ, ДТО, БПЛА), на которых русский словарь разваливается.

Плюс огрублённый стеммер. Проверено на этой базе:

```
to_tsvector('simple', 'Проверка герметичности цилиндров')
  @@ to_tsquery('simple', 'герметичность:*')   → false
  @@ to_tsquery('simple', 'герметичност:*')    → true
```

Отбрасывание последнего символа превращает слово в префикс, под который
подходят все его формы. Полноценный стеммер требует русского словаря и
весит больше, чем весь тренажёр.

## Очередь обязана быть настоящей

`QUEUE_CONNECTION=sync` недопустим. При `sync` задача генерации
выполняется внутри HTTP-запроса «начать тренировку»: запрос висит десятки
секунд и упирается в клиентский таймаут — воспроизведено как
`alert: timeout of 60000ms exceeded` при том, что вопросы генерировались.

```bash
QUEUE_CONNECTION=database
php artisan queue:work
```

Запрос возвращает `generating: true` мгновенно, окно опрашивает состояние
каждые 5 секунд.

## Диагностика

```bash
php artisan content:check-exposure     # каталог материалов не отдаётся напрямую
php artisan tutor:quality              # доля пригодных вопросов и скорость
```

В админке: **Настройки → Тренажёр** — галка включения и таблица
состояния движка (адрес, модель установлена или нет, число моделей,
эмбеддинги, очередь). Диагностика и галка разведены намеренно: включённый
тренажёр при неработающем движке не «сломан», он просто не может
работать.

Замер качества — инструмент подбора модели, а не тест:

```
Модель: qwen3:4b
Фрагментов: 3 | просим по 4 вопросов
  фрагмент 0       9.9с  принято 4 из 4
  фрагмент 1       7.6с  принято 4 из 4
  фрагмент 2      19.1с  принято 0 из 4
Принято: 8 из 12 (67%)
```

Доля ниже 40% — тренажёр работает, но вопросы будут готовиться долго.
Ноль пригодных — модель меньше 3B.

## Чего модуль не умеет

* **PDF со сканами** — без OCR материал помечается `empty`, и это
  отдельная задача.
* **Открытые ответы** — оценка свободного текста моделью самое слабое
  место, поэтому тип `open` выключен по умолчанию.
* **Экспорт в банк вопросов** (этап 4 плана) — вопросы тренажёра не
  попадают в `Question`/GIFT ни автоматически, ни через интерфейс. Только
  после ручной проверки методистом.
* **Разговор с тренажёром** — это генератор вопросов по фрагментам, а не
  чат; query rewriting из плана не реализован.

## Проверки

* `tests/Feature/TutorApiTest.php` — границы: чужие материалы, чужие
  сессии, отсутствие эталонов в выдаче, неприкосновенность экзаменов.
* `tests/Feature/TutorGroundingTest.php` — приём и отбраковка вопросов,
  дедупликация, back-check.
* `tests/Feature/TutorVectorStoreTest.php` — оба бэкенда поиска и
  устойчивость к сбою сателлита.
* `tests/Unit/components.tutor.spec.js` — интерфейс: состояние движка,
  скрытый эталон, объяснение «вопросы кончились».
* `tests/E2E/tutor.spec.js` — сквозной цикл. Пропускается, если движок
  недоступен или модель не дала пригодных вопросов: это состояние
  окружения, а не проверяемое поведение интерфейса.
