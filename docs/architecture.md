# Карта проекта

Файл отвечает на вопрос «за что отвечает этот класс». Он не пересказывает код, а
объясняет **разделение ответственности** и то, что из кода не следует: где
принимаются решения о доступе, почему файл делает именно это, и какие места
нельзя менять, не сломав что-то другое.

Три правила, которые проходят через весь проект:

1. **Доступ решается в одном месте, а не в каждом контроллере.** Видимость
   курсов — `CourseVisibility`, открытие материала — `CourseAccess`, права —
   `HasRolesAndPermissions` + `PermissionScope`. Контроллеры, которые решают
   «виден ли курс» самостоятельно, — источник уязвимостей.
2. **Роль приходит из двух источников намеренно.** Колонка `users.role` и
   связь `role_user` независимы (см. «Роли и права»).
3. **Приватный контент защищён подписью в пути, а не токеном.** Иначе вложенные
   CSS/JS/картинки курса запрашивались бы без авторизации.

---

## 1. Точки входа: кто кого вызывает

```
routes/web.php ─► SinglePageController (отдаёт оболочку SPA)
                    └─ весь UI живёт в Vue (resources/js), роутер — resources/js/Router/routes.js

routes/api.php ─► middleware: auth:sanctum + permission:a,b (здесь «любое из»)
              └─ Controllers
                   ├─ Support/*  — решения о доступе и выдаче контента
                   ├─ Models/*   — данные и связи
                   ├─ Policies/* — правила «кому можно что» (Gate)
                   └─ Jobs/*     — фоновая генерация вопросов тренажёра
```

`routes/api.php` смонтирован один раз под префиксом `api`; версионирование —
вложенной группой `prefix('v1')`. Поэтому маршрут пишется как `'/v1/login'`.
**Порядок объявления в файле значим**: статические сегменты должны идти раньше
параметризованных, иначе они уйдут в параметр.

## 2. Роли и права

| Класс | За что отвечает |
|---|---|
| `app/Traits/HasRolesAndPermissions.php` | Единый подсчёт эффективных прав: прямые (`permissions_users`) ∪ права ролей (`permissions_roles`) ∪ legacy-алиасы, с fallback на `config('permissions.role_matrix')` **только когда явных назначений нет**. Даёт `hasPermission`, `isSuperAdmin`, выдачу/снятие прав. |
| `app/Models/User.php` | Пользователи. Собирает `fio` из ФИО в хуке, нормализует роль из двух источников, отдаёт `isAdmin/isInstructor/isTrainee/isSuperAdmin`. |
| `app/Models/Role.php` | Роли. Права берутся из pivot `permissions_roles`, а не из одноимённой колонки (она удалена, чтобы связь не перебивалась). |
| `app/Models/Permission.php` | Права. В `saving` выводит slug из имени, если он не задан явно. |
| `app/Support/PermissionCatalog.php` | Каталог прав из `config/permissions.php`: маппинг legacy-алиасов и список защищённых slug. |
| `app/Support/PermissionScope.php` | Кому какие права можно выдавать: администратор — всё, инструктор — только свои (минус `users.permissions`, `system.maintenance`) и только в своей группе. |
| `app/Http/Middleware/CheckUserPermission.php` | Алиас `permission` — «достаточно **одного** из перечисленных прав». Берёт `$request->user()`, а не `Auth::user()`. |
| `app/Http/Middleware/CheckAllPermissions.php` | Алиас `permission.all` — требуются **все** права. |
| `app/Providers/AuthServiceProvider.php` | `Gate::before`: возвращает `true` только суперадмину, иначе `null`, чтобы не перебивать остальные политики. |
| `app/Console/Commands/SyncPermissions.php` | `permissions:sync` — синхронизирует каталог из конфига с таблицами `permissions`/`permissions_roles`. |

**Ловушки, из-за которых ломается раздача прав:**

- `users.role` и `role_user` — два независимых источника. `chroll` синхронизирует
  только `role_user`, поэтому пользователь с ролью из UI считался «без роли» и не
  получал базовых прав матрицы.
- Роль при регистрации назначается **по правам актора**, а не по телу запроса:
  без `users.create` роль принудительно «Обучаемый», а `group_id` остаётся `null`.
- Право «есть у админа» проверяется тремя способами (`isAdmin`, `isSuperAdmin`,
  `Gate::before`); расхождение любых двух даёт 500 на логине или 403 там, где
  ожидался проход.

## 3. Курсы, специальности, группы

| Класс | За что отвечает |
|---|---|
| `app/Models/Course.php` | Курс. `belongsTo` категория/самолёт, `hasMany` модули и учебные записи, `manyToMany` инструкторы и студенты. Алиасы `name`/`description` для API v1. |
| `app/Models/Category.php` | Специальность. Полностью `$guarded=[]`. |
| `app/Models/Aircraft.php` | Тип ВС. Поле `path` задаёт каталог контента `private/<путь>`. |
| `app/Models/Aukstructure.php` | Модуль курса с самоссылкой `parent/children`. |
| `app/Models/Group.php` | Учебная группа — точка привязки всех проверок области видимости. |
| `app/Models/Group2learning.php` | Запись «группа записана на курс **в рамках своей специальности**» (`group_id, course_id, category_id, parent_id`). Единственный источник прав на курсы и материалы. |
| `app/Support/CourseVisibility.php` | **Видимость** в списках: обучаемый видит курсы своей группы, управляющие курсами — всё, без группы — ничего. |
| `app/Support/CourseAccess.php` | **Открытие материала**: записан через свою группу либо управляет курсами. Завершается `abort(403)`. |
| `app/Http/Controllers/CatalogController.php` | Витрина курсов и самостоятельная запись/отписка своей группы. `CourseVisibility` здесь намеренно **не** применяется — иначе записаться было бы не на что. |
| `app/Http/Controllers/CoursesListController.php` | «Учебный план»: список курсов через `CourseVisibility`. |
| `app/Http/Controllers/CourseController.php` | CRUD курсов, манифест, открытие материала через `CourseAccess`. |
| `app/Http/Controllers/AircraftController.php` | Списки папок-классов и импорт самолёта: `Aircraft`, `Course`, `Aukstructure`, `Link`, `Category` и pivot-таблицы строятся из `imsmanifest.xml` **в одной транзакции**. |
| `app/Http/Controllers/FileLoadAndExtractController.php` | Загрузка zip курса и распаковка в `storage/app/public/private`. |
| `app/Http/Controllers/Group2learningController.php` | CRUD учебных записей, область — `Group2learningPolicy`. |

**Почему запись несёт `category_id`.** Один курс бывает привязан к нескольким
специальностям. Проверка «есть запись на курс» дала бы лётчику материалы
радиста. Поэтому единица права — пара `(course_id, category_id)`.

## 4. Приватный контент: подпись и выдача

Это самый тонкий узел проекта. Здесь байты файла — единственное место, где они
целиком проходят через PHP.

| Класс | За что отвечает |
|---|---|
| `app/Support/PrivateContentSigner.php` | Подписанные URL: HMAC-SHA256 от `aircraft|auk|expires` на `APP_KEY`, TTL 30 минут. Подпись встраивается **в путь**, чтобы наследовалась вложенными ресурсами. |
| `app/Http/Middleware/ValidatePrivateContentSignature.php` | Проверка подписи; 403 на подделке и по истечении срока. Маршрут намеренно без `auth:sanctum`: вложенные ресурсы идут без заголовка Authorization. |
| `app/Support/PrivateContent.php` | Безопасная работа с путями: санитизация сегментов (запрет `..`, разделителей, NUL, закодированных разделителей) и сверка `realpath` с корнем контента. |
| `app/Http/Controllers/PrivateController.php` | Выдача: полный ответ для `index.html`, поток для вложенных файлов, либо `X-Accel-Redirect`. Здесь же выдача подписанного префикса (`signedUrl`). |
| `app/Support/ContentDelivery.php` | Режим выдачи: `php` или `nginx`. Читает `settings.content_delivery` с TTL 5 секунд. **X-Accel включается только если запрос помечен заголовком из `APP_KEY`** — иначе при `php artisan serve` Symfony отдал бы пустое тело со статусом 200. |
| `app/Console/Commands/ContentNginxConfigCommand.php` | `content:nginx-config` — печатает готовый фрагмент nginx (внутренний путь, корень хранилища, метка) из тех же источников, что и приложение. |
| `app/Console/Commands/RelocateContentCommand.php` | `content:relocate` — перенос каталога материала за пределы `public/`. Считает файлы и байты до и после, отказывается переносить внутрь `public/` или `storage/app/public`, умеет `--dry-run`. |
| `app/Console/Commands/CheckPrivateContentExposure.php` | `content:check-exposure` — проверяет, что контент не отдаётся веб-сервером напрямую. |

Три независимых слоя защиты: подпись → `realpath` → `internal`-location nginx.

**Про nginx.** Защита не ослабевает: единственный вход — Laravel, `internal`
делает location недоступным снаружи (прямой запрос даёт 404). `secure_link`
добавлять **не надо**: подпись наследуется относительными ссылками, а
`secure_link` требует отдельного токена на каждый ресурс и ломает отрисовку.

**Где лежит каталог контента.** `storage/app/courses/private/`, то есть
вне `public/`. Раньше он был в `storage/app/public/private/`, и
`php artisan storage:link` (обычный шаг деплоя) открывал весь материал по
`/storage/private/...` без проверки подписи. Перенос выполнен командой
`content:relocate`; путь задаётся `COURSES_PATH` (по умолчанию — новое
место), и единственный потребитель этого пути в коде — сам конфиг, так
что менять нужно `.env` и `alias` в nginx, а не код.

## 5. Экзамены и банк вопросов

| Класс | За что отвечает |
|---|---|
| `app/Models/Exam.php` | Экзамен — пара `aukstructure_id + category_id` для отбора, окно `opens_at/closes_at`, `max_attempts`, `passing_score`. `questionQuery()` применяет лимит вопросов, `stateFor()` — статус. |

одни вопросы, а засчитывались другие.

## 6. AI-тренажёр

Отдельный контур: свои таблицы `tutor_*`, своё право `tutor.use`,
**не влияет на экзамены** — ни `exam_attempts`, ни банк вопросов не трогает.

| Класс | За что отвечает |
|---|---|
| `app/Models/TutorMaterial.php` | Материал = пара `(course_id, category_id)`. `isReady()` требует `status=indexed` и ненулевого числа фрагментов. |
| `app/Models/TutorChunk.php` | Фрагмент материала — единица работы. `scopeRelevant` ищет по `to_tsvector`. |
| `app/Models/TutorSession.php` | Сессия с окном контекста; `generation_started_at` — признак «вопросы готовятся». |
| `app/Models/TutorItem.php` | Сгенерированный вопрос. `toPlayerArray()` **не отдаёт** эталон и цитату — иначе тренажёр проходится на автомате. |
| `app/Models/TutorResponse.php` | Ответ пользователя. `ungraded` ≠ `wrong`: недоступность движка не должна превращаться в ноль. |
| `app/Jobs/GenerateTutorQuestions.php` | Фоновая генерация. Требует запущенного `php artisan queue:work`. Снимает метку генерации всегда, даже при падении движка. |
| `app/Support/Tutor/TutorMaterialIndexer.php` | Пересборка материалов: по одному материалу на каждую пару (курс, специальность), текст курса читается один раз на все пары. |
| `app/Support/Tutor/TutorMaterialExtractor.php` | Извлечение текста из HTML курса; каталоги `GIFT/app/models/orig/eDoc` исключены — тренажёр физически не читает банк экзамена. |
| `app/Support/Tutor/TutorQuestionGrounding.php` | Промпты и строгая приёмка: цитата обязана дословно найтись во фрагменте, для `mcq` эталон обязан быть среди вариантов, дедуп по fingerprint. |
| `app/Support/Tutor/TutorAnswerGrader.php` | Проверка ответа. `mcq`/`short` — кодом, `open` — моделью строго против эталона и цитаты. |
| `app/Support/Tutor/TutorAccess.php` | Что показывать пользователю: материалы по парам из `group2learnings`. |
| `app/Support/Tutor/TutorClient.php` | HTTP-клиент локального движка (Ollama/llama.cpp): `health()`, `generate()` c `think=false`, необязательный `embed()`. |
| `app/Support/Tutor/TutorSettings.php` | Переключатель `settings.tutor_enabled`. По умолчанию **выключен**. |
| `app/Support/Tutor/PostgresVectorStore.php` | Поиск по `tutor_chunks` через FTS. Всегда доступен. |
| `app/Support/Tutor/SatelliteVectorStore.php` | Векторный поиск через Python-сателлит с ChromaDB. Любой сбой не ломает тренажёр — вызывающий переключается на Postgres. |
| `app/Support/Tutor/TutorUnavailableException.php` | Отдельный тип «движок недоступен», чтобы отличать состояние окружения от плохих вопросов. |
| `app/Console/Commands/TutorQualityCheckCommand` (`TutorQualityCheck`) | `tutor:quality` — доля пригодных вопросов. |
| `app/Console/Commands/TutorSeedDemoQuestions.php` | `tutor:seed-demo` — демонстрационные вопросы. |

**Что здесь ломает интерфейс по неочевидной причине.** Генерация идёт в фоне.
Без `php artisan queue:work` задание не берётся никем: интерфейс крутил
спиннер молча, и понять, что запуск не в порядке, было невозможно. Теперь
при превышении `tutor.worker_stall_seconds` UI прямо пишет, что не запущен
обработчик очереди.

## 8.1. Файловый менеджер

Подробно — `docs/file-manager.md`. Здесь только «за что отвечает класс».

| Класс | За что отвечает |
|---|---|
| `app/Support/FileManager/EntryName.php` | Единственная проверка имени файла и папки. Запрещает разделители, NUL, ведущую/хвостовую точку. Отвергает, а не чистит: молчаливая очистка создала бы объект, которого пользователь не просил. |
| `app/Support/FileManager/Location.php` | Арифметика путей и диск. **Не знает о базе**: что такое папка и кому она принадлежит, решает `FolderTree`. Проверка `isInsideUserRoot` сверяет `realpath` с корнем пользователя — это ловит симлинк, прошедший проверку имени. |
| `app/Support/FileManager/FolderTree.php` | Дерево папок: кто чей, путь от корня, зацикливание, свободное имя. Родитель проверяется на принадлежность пользователю. |
| `app/Support/FileManager/FileManagerService.php` | Операции над папками и файлами. Порядок «сначала диск, потом база» и откат зафиксированы здесь, а не в контроллере. |
| `app/Support/FileManager/ChunkUploadService.php` | Протокол загрузки по частям. `init` идемпотентен по отпечатку файла — это докачка. Размер каждой части сверяется с ожидаемым, иначе объявленный размер ничем не ограничен. |
| `app/Http/Controllers/FileManagerController.php` | Каталоги, папки, файлы, скачивание. Контроллер тонкий намеренно. |
| `app/Http/Controllers/ChunkUploadController.php` | Приём частей. Отдельный от `FileManagerController`: у него другая форма запроса (тело — данные, а не JSON). |
| `app/Console/Commands/FileLimitsCommand.php` | `files:limits`: сравнивает размер части с `post_max_size` и печатает готовые строки nginx. |
| `app/Console/Commands/PruneFileUploadsCommand.php` | `files:prune-uploads`: убирает брошенные загрузки и их части. |

**Почему файлы лежат вне `public/`.** Каталог `storage/app/public`
попадает под корень веб-сервера через `php artisan storage:link`, и всё,
что туда легло, становится доступно по адресу `/storage/…` без проверки
прав. Старый `FilesController::upload` писал на диск по умолчанию, и одна
смена `FILESYSTEM_DISK=public` тихо делала личные файлы доступными всем,
у кого есть ссылка.

**Что не ломает менеджер.** Старый `POST /api/files/add` и компонент
`FileLoadSimple.vue` (его подключают формы курсов) продолжают работать;

показываются.

## Объявления

Объявления адресные: для всех, для групп, курсов и роли одновременно (комбинация флагов и json-массивов в `announcements`). Видимость решает `Announcement::visibilityFor()` — по тем же признакам, что и меню: роли из `role_user`, а не строка `users.role`. Объявление для группы А не должно всплывать в ленте группы Б, поэтому отдавать «всем авторизованным» нельзя.

Редактору показывается вся лента, включая адресованное другим группам: иначе он не увидел бы собственную публикацию и решил бы, что она удалена.

Публикация — новое право `announcements.manage`, а не `content.manage`: объявление это сообщение людям, а не учебный материал. Пустая аудитория трактуется как «всем» — иначе объявление без уточнения не увидел бы никто, и автор решил бы, что публикация сломана.

## Идемпотентные демо-данные

Повторный запуск `php artisan db:seed` не должен ничего ломать и ничего удваивать. Это оказалось неочевидно: у большинства таблиц **нет уникального индекса** на естественном ключе (проверено: уникальны только `users.fio`, `permissions.slug`, `roles.slug`), поэтому `insert()` молча создавал копии, а `upsert()` падал с «нет уникального ограничения… ON CONFLICT».

Отсюда решение: везде `updateOrCreate`/`updateOrInsert` или `firstOrCreate` по естественному ключу — без изменения схемы.

Что это даёт:
- `CategorySeeder` — по `code` (по коду ищутся уроки курса);
- `CourseSeeder` — по `path` (путь к материалам);
- `AircraftSeeder` — по `path`;
- `GradeSeeder` — по `boundary`, `SettingSeeder` — по `name`;
- `UserSeeder` — по `fio`, причём **пароль пишется только при создании**: при вставке он обязателен (NOT NULL), а при обновлении затирал бы пароли живых людей при каждом запуске сидеров;
- `CourseLessonsSeeder` — с префиксом `DEMO-` у сгенерированных уроков, чтобы удаление своих строк перед вставкой не съело уроки, загруженные импортом из XML;
- записи групп на курсы в `DatabaseSeeder` — `firstOrNew`, иначе каждый прогон добавлял по три «периода обучения» на курс.

Побочный эффект: `AircraftSeeder` теперь использует реальные каталоги материалов (`БПЛА`, `КЛЕН`), а `CourseLessonsSeeder` — пять крупнейших HTML-файлов, иначе страница материала показывала пустое окно: прокручивать нечего, и проверка падала на материале в 30 КБ.

## Демо-данные

Сидеры собирают связный демо-набор, а не просто заполняют таблицы. Раньше курсы создавались без самолётов, категории — без самолётов и связей, уроки не создавались вовсе, а пути самолётов («Ка-52», «Ми-28») не совпадали с реальными каталогами материалов. Схема это допускает, но интерфейс на таких данных пуст: каталог группирует курсы по самолёту, дерево курсов строится из уроков, фильтр по категории ищет уроки по коду категории, а страница материала ищет файл по `private/<самолёт>/<курс>/<файл>`.

`CourseLessonsSeeder` закрывает разрыв: привязывает категории и курсы к самолётам, создаёт уроки и связи `category_course`, а для первого курса первого самолёта — пять разделов с материалом (`type = 3`) и ссылками на реальные файлы. Путь курса в базе — это **сегмент** каталога (`04`), а не абсолютный путь: `getlink` сам собирает полный путь.

Материальные разделы получают самые крупные HTML-файлы намеренно: проверки прокрутки открывают материал и ждут кнопку «вверх», а у документа в 30 КБ прокручивать нечего. Сидер идемпотентен — свои разделы он пересоздаёт, чужие не трогает.

Проверка полноты переводов: `scripts/i18n_check.py` — все ключи, которые использует код, должны существовать в обоих словарях.

## Отчёты и аналитика

`/reports` собирает разрез в одном ответе: записи групп на курсы, экзамены, прогресс по урокам, активность и шесть месяцев динамики. Фильтры (период, группа, курс) применяются в SQL, а не в браузере — отчёт за месяц по одной группе не должен тянуть в память все строки за все годы.

Период длиннее года обрезается: без этого «за всё время» упирается в память.

Пустые значения отдаются как `null`, а не `0`. Группа без попыток не провалила экзамены — у неё их не было, и «0% успеваемости» читается как обвинение.

Границы видимости те же, что на дашборде: администратор и те, у кого есть `groups.manage`, видят всё; остальным подставляется их группа.

## Домашние задания

Задание привязано к курсу, уроку и группе: список чужих групп обучаемому недоступен, а черновики (без `published_at`) не показываются вовсе.

Область преподавателя задаётся **правом**, а не «его группой»: отдельного назначения преподавателя на группу в системе нет. Если бы на странице заданий действовало другое правило, чем в отчётах и грейдбуке, одно и то же право давало бы разный объём данных на разных страницах.

Пересдача обновляет ту же строку (уникальный индекс по паре «задание + обучаемый») и снимает старую оценку: иначе в журнале было бы три работы на одно задание, а обновлённая работа показывала бы балл за прошлую версию.

Оценка сверяется с `max_score` задания, а максимум нельзя уменьшить ниже уже выставленных оценок — иначе в журнале появляется «12 из 5».

**Дедлайн проверяется на сервере.** Скрытие формы после срока — удобство, а не правило: запрос, отправленный в обход интерфейса, принимался и попадал в журнал как вовремя сданная работа.

## Палитра команд

Палитра (`Ctrl`-кнопка в шапке) показывает разделы и действия, глобальный поиск — данные (курсы, группы, файлы). Сочетание **Ctrl/Cmd+K осталось за поиском**: оно было у него раньше, и перехват ломал бы привычку.

Команды палитры строятся из `utils/navigationVisibility` — того же хелпера, что и боковое меню. Отдельный список разошёлся бы с меню при первой правке: пункт скрыт по правам в меню, а палитра продолжает его предлагать, и пользователь получает 403 вместо раздела.

Переключатели в палитре идут через общие утилиты темы и плотности, а не через локальные флаги: своя реализация переключала бы «на противоположное», и одна кнопка вела бы себя иначе, чем вторая.

## Бланк сертификата

Настройки бланка (организация, подписант, логотип, примечание) лежат в отдельной таблице-синглтоне `certificate_settings`, а не в общих `settings`: у них есть предметная область и форма, и в плоском ключ-значение брендинг сертификата потерялся бы среди прочих записей.

Право `certificates.manage` отдельное от `content.manage`: бланк — официальный документ, и его настраивает тот, кто отвечает за выпуск, а не любой методист курса.

Настройки едут вместе с сертификатом (`GET /api/my/certificates/{id}`), а не отдельным запросом со страницы печати: иначе лист зависел бы от двух ответов и мог напечататься с настройками от прошлого сохранения.

`remove_logo` шлётся отдельным флагом, а не пустой строкой: пустое значение сервер обязан считать «не менять», иначе убрать логотип было бы нечем.

Имя файла логотипа случайное (`Str::random`), а не исходное: имя приходит от клиента и может содержать путь или чужую расшифровку. Старый файл удаляется при замене — иначе публичный диск рос на каждой правке.

Форма размечается полями через слот `FormField`: `v-model` на самом `FormField` оставил бы `<label for>` без цели, и подпись перестала бы быть подписью.

## Маска телефона и валидация

Маска существует для ввода, а не для хранения: в поле видно «+7 (999) 000-00-00», в модель уходит «+79990000000».

Раньше наружу эмитился отформатированный вид, и значение из 17 символов уходило в `varchar(16)` — Postgres отвечал «String data, right truncated», то есть форма падала с **500** на ровном месте, а человек видел «Ошибка сервера» вместо подсказки о поле. Разделители убираются регуляркой `[^\d+]`: `unmask()` по шаблону не годится, он теряет литералы маски и вместе с ними код страны.

Бэкенд теперь валидирует изменяемые поля пользователя (`PATCH /api/user/{id}`), а не пишет `request('...')` напрямую: слишком длинное значение даёт 422 с указанием поля, а не 500.

## Разметка форм и тесты

Поле с меткой `FormField` размечается как `.u-field > label + .v-input`, а не `.v-input > label`. Поиск «label внутри .v-input» находил пустоту на правильной разметке — такие локаторы в E2E заменены на устойчивые к структуре.

`FormActions` и `FormCard` берут подписи кнопок из локализации: дефолтом стоял русский «Сохранить», и в английском интерфейсе форма оставалась русской.

## Уведомления: кто создаёт

Колокольчик и API уведомлений появились раньше, чем создатели событий, и колокольчик был всегда пуст. Создание вынесено в `App\Support\Notifications` и подключено к трём точкам:

- **сдача экзамена** (`ExamController::submit`) — уведомление получает преподаватель (`exams.manage`), и только при успешной сдаче: неудачные попытки в ленте превращались бы в шум;
- **ответ в теме форума** — уведомляется автор вопроса; ответ преподавателя дополнительно приходит тем, кто отвечал и ждал разбора;
- **публикация объявления** — уведомляется ровно та аудитория, которая увидит объявление (`Announcement::visibilityFor`), иначе пришло бы человеку из чужой группы, а по ссылке его ждал бы 404.

Автор действия уведомление о своём действии не получает, а повторное событие с тем же `data->dedup_key` не создаёт вторую запись. Сбой рассылки никогда не превращает уже выполненное действие в ошибку: результат экзамена записан, объявление создано — терять их из-за недоступного колокольчика незачем, поэтому всё обёрнуто в `try` + `report`.

## Восстановление пароля

Вход в систему идёт по ФИО, поэтому восстановление пароля тоже запрашивается по ФИО, а не по email: требовать то, чем человек не входит, бессмысленно. В `password_resets` добавлена колонка `fio` — идентификатор для поиска, `email` остался адресом доставки.

Ответ на `/api/password/forgot` одинаков при любом исходе: неизвестное ФИО, найденный пользователь без почты и нормальный запрос получают один и тот же 200 с текстом «если ФИО найдено…». Иначе по телу ответа можно было бы перебрать существующие ФИО. Токен при этом создаётся всегда — иначе по времени ответа тоже перебор.

Токен одноразовый (удаляется при использовании и при новом запросе) и живёт час. Смена пароля сбрасывает `remember_token`: оставленная в браузере сессия не должна переживать смену пароля. Письмо отправляется через `ShouldQueue` — недоступность SMTP не превращает восстановление в ошибку 500, а запрос повторяется молча.

## Аватар

Колонка `users.avatar` была объявлена как `json` с комментарием «filename path», то есть не тем типом, который в неё кладут: загрузка падала с «неверный синтаксис для типа json». Миграция меняет тип на `varchar(512)`; хранится ровно один путь, структура там не нужна.

Файл кладётся в `storage/app/public/avatars/{user_id}` под sha256-хэшем имени — исходное имя не используется, иначе пользователь мог бы перезаписать чужой файл или угадать путь. Фронт строит URL сам: в ответе лежит относительный путь.

После загрузки обновляется **только** аватар (мутация `SET_USER_AVATAR`), а не весь объект пользователя: перезапись всего user стёрла бы права и роль, которых в ответе загрузки нет.

## Расписание обучаемого

`/my/schedule` — отдельная страница от `/calendar`: календарь методиста отдаёт фильтры по всем группам, а здесь контроллер сам подставляет группу пользователя. Показывать фильтры по группам обучаемому незачем — контроллер всё равно их игнорирует, и такой интерфейс только вводил бы в заблуждение.

## Метрики и графики

`trends` в сводке админ-дашборда: попытки по шести последним месяцам и успеваемость по группам. Месяцы считаются в PHP, а не оконной функцией SQL — проект не использует `generate_series`, а отправлять наружу все попытки ради подсчёта по месяцам означало бы десятки тысяч строк без выигрыша.

Пустые месяцы остаются в ряду с нулём: пропуск месяца без попыток сжал бы график и создал бы впечатление «данных нет».

Графики рисуются штатным `ChartsKit` (`components/ui/charts`) — он уже был в проекте и не использовался. Свой второй SVG был удалён: два разных графика в одном интерфейсе разъезжаются по цветам и сетке.

## Форум

Вопросы живут внутри курса: тема привязана к `course_id` и, необязательно, к уроку (`aukstructure_id`). Отдельного раздела «Форум» в меню нет намеренно — вопрос без курса не имеет смысла, а пункт меню привёл бы в пустоту; ссылка стоит в манифесте курса.

Чтение и участие идут по доступу к курсу (`CourseAccess`), а не по отдельному праву: тема по закрытому курсу не должна показываться даже через поиск. Приватность темы задаётся `group_id`, а не флагом «закрыто» — она всегда привязана к конкретной группе. Руководитель (`groups.manage`) видит приватные темы: без этого он не увидит жалоб из групп, за которые отвечает.

Модерация (`forum.moderate`) отделена от участия: закрепить, закрыть тему и отметить решение может преподаватель. Решением может быть только ответ из этой же темы, иначе можно было бы сослаться на чужой пост. Автор удаляет свою тему, только если на неё ещё никто не ответил — иначе это уничтожение чужого ответа.

Счётчик просмотров увеличивается на открытии темы, а не на перечислении в ленте: иначе лента «накручивала» бы просмотры сама себе.

## Проверка кода сертификата и SPA-fallback

Публичная проверка кода не должна попадать в SPA-fallback: маршрут объявлен с регуляркой `{18}`, и код не той длины тихо уходил в fallback, который отвечает HTML. Код держится ровно 18 символов — подпись урезается по модулю `36^6`, иначе `hexdec` от 8 hex-символов давал 7 символов в base36.

Сам fallback снимает с себя `StartSession`, `AuthenticateSession` и `ShareErrorsFromSession`: guard по умолчанию — sanctum, у него нет `viaRemember`, и любой несуществующий `/api/*` отвечал 500 вместо 404. Проверка `tests/Feature/ApiFallbackTest.php` не даёт этому вернуться.

## Грейдбук преподавателя

Журнал «обучаемые × экзамены» отдаёт сырой счёт и границы, а пятерку считает из них. Оценка **не хранится готовой цифрой**: если бы она лежала в таблице, то после смены границ в `grade_boundaries` весь журнал оказался бы неверным и пересчитывать его пришлось бы вручную.

Из автоматических попыток берётся лучшая, а не последняя — иначе один неудачный повтор стирал бы результат.

Ручная оценка преподавателя (устный ответ, лабораторная) лежит в отдельной таблице `grade_overrides` и перекрывает автоматическую: правкой `exam_attempts` это сделать нельзя, там хранится сырой счёт. Пустая оценка снимает перекрытие, и ячейка снова показывает автоматический результат. Автоматическая оценка при этом остаётся в ответе — видно, что перекрыл преподаватель.

Доступ — только `grading.manage`, и на запись тоже: преподаватель не может поставить оценку человеку из другой группы. Выгрузка CSV собрана на сервере с разделителем `;`, кавычками по RFC 4180 и BOM — без BOM Excel не открывает кириллицу, а запятые в ФИО и названиях экзаменов разъезжают файл на столбцы.

## Сертификаты

Сертификат об окончании курса — печатная HTML-страница, а не готовый PDF: в проекте нет генератора PDF, а печать браузера даёт тот же документ с тем же кодом проверки. Панель кнопок скрывается в `@media print`, на лист выводятся рамка, текст и код.

Условие выдачи: закрыты все уроки курса (`lesson_progress`, 100%) **и** сданы все назначенные по курсу экзамены. Окончание курса по датам само по себе сертификата не даёт — иначе его можно было бы напечатать по любому прошедшему сроку.

Код проверки — 18 символов: id пользователя и id курса в base36 (по 6 символов) плюс 6 символов HMAC от пары «пользователь:курс». Поэтому `GET /api/certificates/verify/{code}` работает без авторизации (у получателя сертификата нет аккаунта) и делает два точечных запроса, а не перебор всех пар «пользователь × курс». Подделать код без ключа приложения нельзя.

## Прогресс по урокам

Посещения материалов раньше жили только в localStorage браузера, поэтому «продолжить обучение» и процент на дашборде терялись при смене устройства и вообще не существовали у другого браузера.

Теперь состояние в таблице `lesson_progress` — по одной строке на пару (пользователь, урок из `aukstructures`). Пишется при открытии урока (`POST /api/my/progress`), 100% засчитывается при прокрутке материала до конца. Процент не уменьшается, но сбрасывается через `DELETE /api/my/progress/{lesson}`.

Процент по плану на дашборде считается взвешенно по числу уроков в каждом курсе: один открытый урок из двадцати больше не делает весь план «на 100%». «Продолжить» возвращает к последнему просмотренному уроку и файлу внутри него.

Доступ к прогрессу проверяется через `CourseAccess`, урок обязан принадлежать тому же курсу — иначе можно было бы «завершить» чужой раздел.
